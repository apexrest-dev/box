# ReferenceTableCell — посилання в таблиці

## Два окремі режими

```text
DISPLAY:  Обслуговування ПЗ

EDIT:    [Обслуговування ПЗ                ][▼][×][…]
```

## Display mode

- показується лише текстове представлення;
- немає кнопок, popup чи меню `ReferenceField`;
- правий клік і клавіші належать таблиці;
- контекстне меню визначається `ENTITY_TABLE_UK.md`/`DOCUMENT_LINE_TABLE_UK.md` і ще має бути окремо погоджене;
- правий клік спочатку робить клітинку поточною.

## Edit mode

- використовується повний `ReferenceField`/`ReferenceEditor` із `REFERENCE_FIELD_UK.md`;
- його popup і три маленькі кнопки `▼` (вибрати), `×` (очистити), `…` (відкрити), контекстне меню й клавіші повністю активні;
- події редактора не передаються таблиці;
- `Enter`/`Tab` підтверджують, `Escape` скасовує;
- подвійний клік, `F2` або початок введення можуть запустити edit mode відповідно до правил таблиці.

## Insert і права

- display mode: `Insert` належить таблиці й може додавати рядок;
- edit mode: `Insert` належить `ReferenceEditor` і означає `Новий`;
- без `canCreate` клавіша споживається редактором і не додає випадково рядок таблиці;
- право створення елемента довідника не дорівнює праву додавання рядка документа.

## Commit

Клітинка не викликає setter доменного об'єкта. Вона передає типізовану подію у `ViewModel`, наприклад `ChangeGoodsReceiptLineProduct`, а таблиця відображає серверний результат.

## Віртуалізація

- при повторному використанні `TableCell` скасовуються popup і незавершені пошуки;
- `updateItem` повністю очищає graphic/text для порожньої клітинки;
- асинхронна відповідь не може потрапити в інший рядок;
- обробники не накопичуються під час reuse.

## Обов'язкові тести

- різні меню display/edit;
- перехід між режимами;
- Insert у двох режимах і без права;
- commit/cancel;
- reuse віртуалізованої клітинки;
- застарілий async search.
