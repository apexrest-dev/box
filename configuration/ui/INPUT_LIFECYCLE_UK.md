# Життєвий цикл введення реквізиту

## Призначення

Це спільний контракт для кожного реквізиту форми та кожного реквізиту рядка табличної частини. Він не переносить бізнес-логіку в JavaFX, а визначає моменти, у які UI починає редагування і підтверджує готове значення.

## Обов'язкові події

Кожний UI-реквізит має дві логічні події:

1. `inputStarted` — початок введення;
2. `inputCommitted` — завершення введення.

Вони обов'язково присутні в контракті компонента. Якщо спеціальна поведінка не потрібна, використовується стандартна реалізація бібліотеки; створювати окремий порожній Java-метод для кожного поля не потрібно. Паспорт все одно містить рядок цього реквізиту й явно показує стандартний або спеціальний обробник.

Для реквізиту рядка обидві події отримують стабільний `lineId`. Номер рядка не використовується як ідентичність.

## Початок введення

`inputStarted` викликається один раз під час входу в режим редагування: отримання фокусу редактором, натискання клавіші введення в активній клітинці або відкриття вибору.

UI може:

- виділити текст і встановити курсор;
- відкрити popup, календар, калькулятор або контекстний пошук;
- застосувати вже отримані від сервера capabilities;
- завантажити варіанти типізованим запитом, якщо це передбачено паспортом.

UI не розраховує бізнес-значення і не вирішує, чи дозволена господарська операція.

## Завершення введення

`inputCommitted` викликається один раз після підтвердження готового значення:

- `Enter`, `Tab` або погоджений перехід фокусу;
- вибір елемента довідника;
- підтвердження календаря або калькулятора;
- інша явна дія commit компонента.

Введення кожного символу не викликає серверну команду. `Escape` скасовує редактор і не змінює бізнес-значення. Якщо значення не змінилося, подія завершує локальний режим редагування, але серверний запит за замовчуванням не надсилається.

Під час зміни UI:

1. завершує парсинг і локальну перевірку формату;
2. створює дозволену типізовану команду конкретного поля;
3. додає ID об'єкта або чернетки, версію та, для таблиці, `lineId`;
4. надсилає команду серверу;
5. відображає повернутий актуальний стан або структуровану помилку.

Універсальна команда на кшталт `ChangeField("fieldName", value)` заборонена.

## Посилальні поля

Набраний пошуковий текст не є вибраним значенням. Для посилання `inputCommitted` настає після вибору конкретного типізованого ID, явного очищення або іншої погодженої дії commit.

## Опис у паспорті

Для кожного реквізиту паспорт містить:

| Реквізит | Компонент | Початок введення | Завершення введення | Типізований запит/команда | Серверна реакція |
|---|---|---|---|---|---|
| ... | ... | standard/custom | standard/custom | ... | ... |

Для read-only реквізиту обидві події позначаються як `disabled`. Для розрахункового поля окремо вказується, чи дозволене ручне введення.

## Межа відповідальності

Назви `inputStarted` та `inputCommitted` описують контракт, а не вимагають однакових рядкових методів у всіх класах. Java-контракти мають бути типізованими. UI-обробник керує редактором, а доменний/application-обробник сервера виконує перевірки, перерахунок і збереження.
