# EntityTable — форма списку

## Статус

**Детальні правила ще не погоджені. Не реалізовувати компонент за припущеннями.**

Окремо потрібно обговорити й зафіксувати:

- структуру панелей таблиці;
- display/selection/edit режими;
- повне контекстне меню таблиці;
- гарячі клавіші та пріоритет обробки;
- серверні пошук, фільтри, сортування й пагінацію;
- локальні налаштування колонок;
- множинний вибір;
- відкриття, копіювання, створення, архівацію й видалення;
- права й видимість команд;
- clipboard/export;
- відновлення позиції, виділення та прокручування;
- поведінку різних типів клітинок;
- візуальні та функціональні тести.

## Уже погоджено

- у display mode клітинка використовує поведінку й контекстне меню таблиці;
- меню редактора поля в display mode не діє;
- правий клік має зробити клітинку/рядок поточним перед відкриттям меню;
- `Insert` у display mode може належати таблиці, але точна команда буде погоджена разом із загальними правилами;
- таблиця не містить бізнес-логіки й відображає серверний стан.
- користувач може сортувати список за кожною видимою колонкою натисканням на її заголовок;
- сортування враховує фактичний тип значення: числа сортуються як числа, дати як дати, а не як відформатований текст;
- `F9` створює копію поточного елемента як новий об'єкт без ID, аудиту й службового стану оригіналу;
- команда `Створити копію` з клавішею `F9` присутня у контекстному меню списку, якщо конкретний список підтримує створення копії.

Після обговорення файл заповнюється за структурою `ELEMENT_TEMPLATE_UK.md`. До того часу це блокувальне нагадування, а не специфікація реалізації.
