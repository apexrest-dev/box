# Завдання повного конфігуратора паспортів

## 1. Передумова

Ці роботи виконуються після MVP. Вони роблять конфігуратор повним робочим
середовищем проєктування, але не перетворюють його на runtime-платформу Trade.

## 2. Розширені ревізії

- [x] Стани `DRAFT/AGREED/IMPLEMENTED`.
- [x] Історія автора й часу кожної зміни.
- [x] Порівняння двох ревізій структури, UI і правил.
- [x] Пошук breaking changes.
- [x] Зв'язок нової ревізії з base revision.
- [x] Implementation report із hash паспорта й git commit.

Історія ревізій показує стани, базову ревізію, часові мітки погодження/реалізації та повний журнал редакторських операцій. Порівняння використовує стабільні технічні шляхи, тому коректно зіставляє дочірні елементи після клонування з новими UUID. Потенційно несумісні зміни позначаються окремо. `IMPLEMENTED` встановлюється атомарно лише для `AGREED` після збігу SHA-256 останнього експорту й збереження Git commit та звіту.

## 3. Повні команди, права та залежності

- [x] Користувацькі команди всіх видів об'єктів.
- [x] Permission key, allowed statuses, result і error contracts.
- [x] Права read/create/update/archive/post/unpost.
- [x] Залежності об'єктів і blocking dependencies.
- [x] Пошук використань об'єкта, поля, команди й регістру.
- [x] Попередження перед несумісною зміною.

Права є типовим набором паспорта: регістри мають `READ`, довідники — `READ/CREATE/UPDATE/ARCHIVE`, документи додатково — `POST/UNPOST`. Команда завжди посилається на право свого об'єкта; для користувацької команди обов'язкові контракти результату й помилки, а допустимі статуси задаються лише для документа. Автоматичні залежності виявляються з посилань, рухів, підпорядкованих довідників і бізнес-правил; ручні залежності зберігаються окремо. UI показує використання та попереджає перед несумісними змінами поля або користувацької команди.

## 4. Розширений редактор форм

- [x] Spacing, visibility, label position і format overrides.
- [x] Редактор колонок таблиць, command bars і totals.
- [x] Empty/loading state.
- [x] Команда «Перемістити до групи».
- [x] Перевірка циклів і дубльованого sort order.
- [x] Текстовий preview скороченого опису форми.
- [x] Preview не генерує runtime JavaFX-код.

Табличні вузли є контейнерами паспорта: `OBJECT_LIST` і `TABLE_PART` можуть містити колонки `FIELD`, локальну `COMMAND_BAR` та `TOTAL`; колонки інформаційної таблиці редагуються в її типізованому definition. Для таблиці зберігаються українські тексти порожнього стану й завантаження. Переміщення змінює лише parent і порядок UI-вузла, перевіряє допустиму вкладеність та не дозволяє цикл. Preview формує читабельне текстове дерево паспорта і принципово не створює FXML або JavaFX-код.

## 5. Повна поведінка UI-компонентів

- [x] Остаточний `ReferencePicker` із F4, контекстним меню та open/list actions.
- [x] Text, numeric, money, quantity, date і datetime fields.
- [x] Калькулятор числа та календар.
- [x] Повна поведінка клітинки reference у таблиці.
- [x] Контекстні меню без іконок.
- [x] Узгоджені Insert/F2/F3/F4/Delete/F9.
- [x] Відновлення фокуса й виділення після validation error.

Реалізація міститься в `com.rmk.trade.configurator.ui.control`. Редактори забирають лише свої клавіші: `F4` виконує вибір або відкриває калькулятор/календар, `F3` запускає пошук посилання, `Insert` і `F8` створюють дозволений елемент, `F2` переводить reference-клітинку в редагування, а `Delete` зберігає стандартне текстове видалення. `F9` редактори не перехоплюють: команда копіювання належить активній формі або списку; її реалізація для метаданих входить до блоку 7. Помилка формату або серверної перевірки повертає фокус у редактор, виділяє текст і показує пояснення.

## 6. Пошук і перейменування

- [x] Український пошук об'єктів і реквізитів.
- [x] Українські aliases попередніх назв.
- [x] Контрольоване перейменування.
- [x] Незмінність technical name після AGREED.
- [x] Масова перевірка неоднозначних назв для AI resolver.

F3 переводить фокус у пошук головного дерева. Пошук використовує тільки нормалізовані українські поточні й попередні назви; UUID, `objectKey` та technical name до операторського результату не потрапляють. Перейменування об'єкта або реквізиту атомарно резервує попередню назву як alias. Для реквізитів `lineage_id` переноситься між ревізіями, тому technical name погодженої структури не можна змінити після клонування. Команда «Перевірити назви» формує загальний звіт неоднозначностей для AI resolver.

## 7. Копіювання, видалення та відновлення

- [x] F9 для метаоб'єктів і дозволених дочірніх definitions.
- [x] Перевірка залежностей перед видаленням.
- [x] Архівування замість видалення там, де потрібна історія.
- [x] Відновлення видаленого DRAFT.
- [x] Зрозумілий звіт про каскадні наслідки.

F9 копіює цілий метаоб'єкт або користувацький реквізит DRAFT як нову незалежну сутність; системні definitions не копіюються. Перед Delete показується звіт використань, блокувальних залежностей і дозволеного каскаду вузлів форми. Об'єкт без погодженої історії переходить у відновлюваний `DELETED_DRAFT`, а з `AGREED/IMPLEMENTED` — у незворотний через звичайний UI архів `ARCHIVED`. Обидва стани приховані з активного дерева та resolver.
