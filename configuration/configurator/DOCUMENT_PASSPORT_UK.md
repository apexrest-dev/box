# Паспорт документа в конфігураторі

## 1. Загальне

Обов'язкові поля:

| Поле | Зміст |
|---|---|
| Англійське ім'я | стабільне technical name документа |
| Українська назва | основна назва оператора |
| Технічний ключ | `Document.<Name>` |
| Клас, ID, таблиця, API | цільові технічні імена |
| Бізнес-подія | що фіксує документ |
| Нумерація | формат, унікальність, момент присвоєння |
| Дата | точність і бізнес-зона |
| Підстава | допустимі типи документів |
| Життєвий цикл | статуси й переходи |

Таблиця `cfg_document_passport`:

`revision_id`, `number_policy`, `number_length`, `date_precision`, `base_document_policy`, `deletion_policy`, `posting_required`, `copy_policy`.

## 2. Структура

Базові поля шапки: `id`, `number`, `occurredAt`, `status`, `version` і аудит. Організація, склад, контрагент, договір та валюта не додаються автоматично. Кожне поле і таблична частина мають англійське technical name та українську display name.

Редактор має дві області:

- реквізити шапки;
- дерево табличних частин та їх реквізитів.

Для табличної частини задаються технічна назва, клас рядка, таблиця, стабільний ID рядка, порядок, правила додавання/копіювання/видалення й унікальність.

Поле-посилання вибирає цільовий об'єкт із конфігуратора. Посилання на ще не реалізований об'єкт створює блокувальну залежність.

## 3. Статуси

Редактор переходів задає:

`Початковий статус | Команда | Наступний статус | Право | Умови | Редагованість`.

Потрібно явно визначити редагованість шапки й кожної табличної частини в усіх статусах. Проведений документ фізично не видаляється.

## 4. UI

Обов'язкові форми:

- список або журнал документів;
- форма документа;
- форма вибору, якщо на документ посилаються інші об'єкти.

Форма документа описується деревом `HEADER/CONTENT/FOOTER`. До `CONTENT` додаються вкладки табличних частин, панелі команд, таблиці та підсумки.

Паспорт зберігає:

- розміщення реквізитів шапки;
- вкладки й колонки кожної табличної частини;
- кнопки `Записати`, `Провести`, `Провести і закрити`, `Скасувати проведення`, `Друк`;
- команди таблиць, підвали й підсумки;
- стани доступності за статусом і правами.

Форма документа може містити `QueryTable` за `docs/ui/QUERY_TABLE_UK.md`: рухи документа, взаєморозрахунки, доступні залишки або інші серверні read models. Вона не є табличною частиною і не записується разом із документом.

## 5. Події введення

Для кожного поля шапки й кожного поля кожної табличної частини створюються `INPUT_STARTED` та `INPUT_COMMITTED`.

Подія рядка завжди отримує `documentId/draftId`, `version` і стабільний `lineId`. Номер рядка не є ідентичністю.

Для завершення введення вказуються:

- типізована команда, наприклад `ChangeGoodsLineQuantity`;
- поля-залежності;
- які поля сервер може перерахувати;
- формат поверненого стану: поле, рядок або весь документ;
- поведінка помилки і фокусу.

## 6. Обов'язкові команди

- `NEW` — початок введення нового документа;
- `SAVE` — запис;
- `POST` — проведення;
- `UNPOST` — скасування проведення.

`COPY` описує F9 і створює нову чернетку без ID, номера, аудиту, статусу проведення й рухів.

Кожна команда має права, дозволені статуси, валідації, транзакційну межу, idempotency, optimistic locking, аудит, помилки й результат.

## 7. Розрахунки

Для рядкових і документних підсумків визначаються:

- результат і залежні поля;
- момент перерахунку;
- порядок каскаду «поле → рядок → документ»;
- валюта, precision/scale і rounding;
- ручне перевизначення;
- stored/transient/read-model;
- приклади, включно з `null` і граничними значеннями.

## 8. Проведення й рухи

Редактор рухів дозволяє вибрати погоджений регістр, джерело рядків і зіставити:

```text
Вимір/ресурс регістру <- поле шапки, поле рядка або описаний алгоритм
```

Паспорт фіксує знак руху, період, recorder, lineNumber, умови створення, перевірки залишків, повторне проведення та скасування.

## 9. Зберігання, API та готовність

Описуються таблиця шапки, таблиці рядків, FK, constraints, індекси, DTO, commands, queries, журнал, друк, аудит і міграції двох СУБД.

Погодження блокується без усіх полів, форм, подій, чотирьох обов'язкових команд, статусів, розрахункових правил, рухів і тестових прикладів.
