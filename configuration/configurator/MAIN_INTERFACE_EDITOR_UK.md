# Сторінка конфігуратора «Інтерфейс»

## Призначення

Сторінка `Інтерфейс` керує складом головного меню робочого JavaFX-клієнта Trade. Вона редагує типізоване посилання паспорта об'єкта на елемент системного довідника `Основне меню`; окремої дублюючої таблиці належності не створюється.

## Розташування й відкриття

- у дереві конфігурації існує системний вузол `Інтерфейс`;
- у ньому розміщується вузол `Основне меню` та його розділи;
- сторінка відкривається подвійним кліком або `F2` на `Інтерфейс` чи `Основне меню`;
- кнопка `Інтерфейс` у верхній панелі є швидким переходом до тієї самої сторінки;
- форма створюється Java-кодом без FXML.

## Компонування

Сторінка складається з двох частин:

```text
┌──────────────────────┬───────────────────────────────────────────────┐
│ Основне меню         │ Розділ: Довідники                            │
│ Довідники            │ ▼ Довідники                                  │
│ Документи            │   ☑ Номенклатура                             │
│ Звіти                │   ☐ Контрагенти                              │
│ Налаштування         │ ▼ Документи                                  │
│                      │   ☐ Прибуткова накладна                      │
└──────────────────────┴───────────────────────────────────────────────┘
```

Зліва показуються активні елементи довідника `Основне меню` в порядку `sort_order`. Справа показується дерево доступних метаоб'єктів, згрупованих за видом. Основна назва в обох частинах — українська.

## Правила галочок

- у дерево потрапляють лише активні метаоб'єкти, які мають форму виду `LIST`;
- встановлена галочка означає, що паспорт об'єкта посилається на вибраний зліва розділ;
- встановлення галочки для іншого розділу переносить об'єкт до нього й автоматично прибирає його з попереднього розділу;
- один об'єкт належить рівно одному розділу основного меню;
- зняти єдину галочку без призначення іншого розділу не можна;
- змінювати належність можна лише для `DRAFT`-ревізії;
- для `AGREED` або `IMPLEMENTED` спочатку створюється нова DRAFT-ревізія;
- відсутність форми списку є серверною блокувальною помилкою, навіть якщо клієнт помилково надіслав команду.

## Межа UI і application-шару

JavaFX не переписує весь паспорт і не вирішує самостійно, чи можна додати об'єкт. Галочка надсилає типізовану команду `AssignMainMenuSectionCommand(revisionId, mainMenuSectionId)`. Application-сервіс перевіряє DRAFT-статус, наявність `LIST`-форми та активність розділу; repository атомарно змінює `main_menu_section_id`, версію й аудит ревізії.

## Перевірки

- початкове відкриття правильно відмічає об'єкти вибраного розділу;
- переміщення змінює лише одну DRAFT-ревізію;
- після оновлення сторінки галочка відновлюється з БД;
- об'єкти без `LIST`-форми не показуються;
- погоджена ревізія не змінюється;
- заборонено залишити об'єкт без розділу;
- команда аудіюється як зміна `MAIN_MENU`.
