> Стан схеми конфігуратора: міграції `V001–V025`. `V025` додає версійований
> «Каркас системи», його правила та незмінні релізи конфігурації. `V023` додає системний довідник
> `Основне меню` та обов'язкове посилання ревізії об'єкта на його розділ. Початкові
> елементи: `Довідники`, `Документи`, `Звіти`, `Налаштування`. `V022` додає локальне
> відновлення розміру вікна, пошуку, вибору та розгорнутих вузлів після перезапуску.
> `V021` додає імпорт структурованого
> implementation report, перелік артефактів, часткові результати й ознаку перевірки checksum.
> `V020` додає lifecycle активного
> об'єкта, архів і відновлюваний кошик DRAFT. `V019` додає український пошук,
> aliases попередніх назв і стабільний lineage реквізитів. `V016` додає журнал кожної зміни,
> історію експортів, SHA-256 ревізії, перевірений implementation report та атомарний
> стан `IMPLEMENTED`. У вікні «Історія ревізій» доступні порівняння структури, UI,
> бізнес-правил і позначення потенційно несумісних змін.

# Конфігуратор паспортів Trade

## Призначення

Конфігуратор є design-time застосунком для створення, перевірки, погодження та експорту паспортів облікових об'єктів. Він не створює runtime-об'єкти автоматично і не виконує бізнес-логіку з метаданих.

Погоджена ревізія паспорта експортується як незмінний пакет завдання для агента. За цим пакетом агент реалізує типізований Java-код, міграції, API, JavaFX UI і тести.

## Незмінні правила

- база конфігуратора відокремлена від робочої бази Trade;
- база конфігуратора є джерелом істини для паспортів; експортовані Markdown-файли є похідними артефактами й не редагуються вручну;
- погодження автоматично оновлює пакет вибраного паспорта, а команда `Оновити всі паспорти` синхронізує всі останні погоджені ревізії та `exports/index.json`;
- каркас системи є окремою версійованою сутністю з категоріями архітектури, серверних контрактів, UI-компонентів, шаблонів об'єктів і якості;
- реліз конфігурації фіксує одну погоджену ревізію каркаса та точні погоджені ревізії всіх активних об'єктів;
- редагується лише ревізія зі статусом `DRAFT`;
- `AGREED` є незмінним знімком; зміна створює нову ревізію;
- бізнес-логіка зберігається як структурований опис і Markdown, але не виконується конфігуратором;
- форма описується для постановки задачі агенту, а не для runtime-автогенерації;
- посилання вибираються з реєстру об'єктів і створюють явну залежність;
- кожна іменована сутність має UUID, англійське технічне ім'я та українську операційну назву;
- паспорт об'єкта обов'язково посилається на елемент системного довідника `Основне меню`; команда об'єкта в цьому розділі відкриває його форму списку;
- списки, picker і контекстний пошук використовують тільки українську назву;
- англійське technical name відображається тільки в картці та експортується для коду, API й БД;
- тип вибирається лише із закритого переліку десяти значень у `CONFIGURATOR_TYPE_SYSTEM_UK.md`;
- експорт не допускається, поки обов'язкові поля або блокувальні залежності не пройшли валідацію.
