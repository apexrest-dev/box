# Жорстка система типів конфігуратора

## 1. Закритий перелік

Конфігуратор підтримує рівно десять типів:

| Код | Українська назва | Призначення |
|---|---|---|
| `STRING` | Строка | текстовий реквізит |
| `NUMBER` | Число | ціле або десяткове значення |
| `DATE` | Дата | календарна дата без часу |
| `DATETIME` | Дата-тайм | дата і час |
| `BOOLEAN` | Булеан | логічне значення, прапорець |
| `CATALOG` | Довідник | метаоб'єкт довідника або типізоване посилання на нього |
| `DOCUMENT` | Документ | метаоб'єкт документа або типізоване посилання на нього |
| `TABLE_PART` | Таблична частина | дочірня колекція рядків об'єкта |
| `INFORMATION_REGISTER` | Реєстр відомостей | метаоб'єкт інформаційного регістру |
| `BALANCE_REGISTER` | Реєстр залишків | метаоб'єкт накопичувального регістру залишкового виду |

Порядок у ComboBox незмінний і відповідає таблиці.

## 2. Технічна реалізація

Перелік реалізується:

- Java enum `ConfiguratorType`;
- enum у application-контрактах та експортній схемі;
- CHECK constraints у SQLite;
- enum у YAML schema;
- фіксованим ComboBox у JavaFX.

У БД немає таблиці, через яку користувач може додавати або перейменовувати типи. Невідоме значення відхиляється API.

## 3. Допустимі контексти

`QUERY_TABLE` не входить до десяти типів: це вид UI-вузла, а не тип об'єкта або реквізиту. Типи його колонок використовують дозволену підмножину цього переліку.

`OWNED_CATALOG_TABLE` також не є новим типом. Це UI-вузол, який керує елементами об'єкта типу `CATALOG` із типізованим owner.

### Вид метаоб'єкта

Для `cfg_object.object_kind` дозволені:

- `CATALOG`;
- `DOCUMENT`;
- `INFORMATION_REGISTER`;
- `BALANCE_REGISTER`.

### Структура паспорта

- `STRING`, `NUMBER`, `DATE`, `DATETIME` і `BOOLEAN` створюють звичайні реквізити;
- `CATALOG` і `DOCUMENT` у реквізиті вимагають `reference_target_object_id` відповідного виду;
- `TABLE_PART` створює контейнер `cfg_table_part`, а не значення клітинки;
- `INFORMATION_REGISTER` і `BALANCE_REGISTER` створюють окремі метаоб'єкти; використання запису регістру як реквізиту не допускається без окремого майбутнього правила.

## 4. Параметри типів

`STRING`:

- максимальна довжина;
- однорядковий/багаторядковий UI;
- обов'язковість;
- нормалізація і validation pattern.

`NUMBER`:

- precision;
- scale;
- rounding mode;
- допустимий діапазон;
- формат: звичайне число, кількість, гроші або відсоток.

`DATE`:

- Java-тип `LocalDate`;
- формат відображення;
- календар через F4;
- зберігання в SQLite як ISO `YYYY-MM-DD`;
- стандартний компонент `DateField` із `docs/ui/DATE_FIELD_UK.md`.

`DATETIME`:

- серверний Java-тип `Instant`;
- точність часу: хвилини або секунди;
- календар через F4 і ручне редагування часу;
- зберігання в UTC як ISO-8601;
- локальна часова зона застосовується тільки для введення та відображення;
- стандартний компонент `DateTimeField` із `docs/ui/DATE_FIELD_UK.md`.

`BOOLEAN`:

- Java-тип `boolean` для обов'язкового значення або `Boolean` лише коли паспорт явно дозволяє `null`;
- SQLite-значення `0/1` із CHECK constraint;
- стандартний JavaFX-компонент `CheckBox`;
- український caption описує позитивний стан, наприклад «Видано».

`CATALOG/DOCUMENT`:

- обов'язкова ціль;
- archive/delete policy;
- picker і права відкриття/створення.

`TABLE_PART`:

- технічна й українська назви;
- стабільний ID рядка;
- порядок;
- власний перелік реквізитів;
- правила додавання, копіювання й видалення.

## 5. Системні поля

UUID, version, audit, стан і номер документа є системними полями каркаса. Системна дата документа використовує `DATE` або `DATETIME` відповідно до його паспорта.

Якщо в майбутньому буде потрібний інший новий тип, його не можна імітувати строкою чи числом. Спочатку змінюється це правило, схема, enum, UI-компонент, експорт і тести.

## 6. Валідація

Погодження паспорта блокується, якщо:

- тип не входить до десяти дозволених;
- тип використано в недопустимому контексті;
- reference не має цілі або ціль іншого виду;
- `TABLE_PART` використано як звичайне поле;
- регістр використано як посилання на його runtime-запис;
- параметри `STRING/NUMBER/DATE/DATETIME/BOOLEAN` неповні або суперечливі.
