# Майбутні необов'язкові завдання конфігуратора

## 1. Статус

Ці можливості не блокують MVP або повний локальний конфігуратор. Кожна з них
потребує окремого погодження й, за необхідності, ADR.

## 2. Візуальне проєктування

- [ ] Drag-and-drop вузлів форми.
- [ ] WYSIWYG-preview майбутньої JavaFX-форми.
- [ ] Бібліотека готових layout-шаблонів.
- [ ] Візуальне порівняння двох версій форми.

Preview залишається design-time інструментом і не створює runtime-форми автоматично.

## 3. Командна й мережева робота

- [ ] Кілька користувачів конфігуратора.
- [ ] Авторизація та ролі самого конфігуратора.
- [ ] Мережеве сховище паспортів.
- [ ] Блокування й merge одночасних змін.
- [ ] Перехід design-time БД із SQLite на PostgreSQL.

## 4. Інтеграції

- [ ] Інтеграція з Git.
- [ ] Автоматичне створення задачі або гілки для агента.
- [ ] Імпорт metadata descriptions із наявного Trade.
- [ ] Імпорт обмеженої структури з 1С.
- [ ] Публікація паспорта у зовнішню систему документації.

## 5. Розширений AI

- [ ] AI-помічник заповнення паспорта.
- [ ] Пропозиції залежностей і бізнес-прикладів.
- [ ] Перевірка суперечностей між структурою, UI та правилами.
- [ ] AI-порівняння ревізій.
- [ ] Генерація чернетки implementation task.

AI не отримує права непомітно погоджувати паспорт або виконувати mutation без
явної команди користувача.

## 6. Експлуатація

- [ ] `jpackage` і Windows installer.
- [ ] Автоматичне оновлення.
- [ ] Планове резервне копіювання SQLite.
- [ ] Майстер відновлення пошкодженої бази.
- [ ] Діагностичний пакет і журнал міграцій.
- [ ] Portable-режим.

## 7. Аналітика конфігурації

- [ ] Граф залежностей об'єктів.
- [ ] Звіт складності паспортів.
- [ ] Покриття бізнес-правил тестовими прикладами.
- [ ] Пошук невикористаних полів, команд і UI-вузлів.
- [ ] Оцінка впливу майбутньої зміни.

Майбутня функція додається до активного плану тільки після визначення конкретної
користі, межі та критерію готовності.
