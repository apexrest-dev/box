# Паспорт регістру «ПДВ: зобов'язання й кредит»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-67).
- Ревізія: `r5` (F-TAX-01).
- Розділ меню (Taxi): `Фінанси` → «ПДВ» → «Реєстр податкових накладних» (сторінка 630).
- Аналог у 1С:УТ 11: РегистрНакопления.НДСПредъявленный / НДСЗаписиКнигиПродаж (спрощено — один регістр
  оборотів за податковими накладними).
- Функції каталогу: `F-TAX-01`.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|
| Таблиця | `reg_vat_mv` (регістр оборотів; рухи лише проведенням `DocTaxInvoice`, `reg_vat_mv_biud`) |
| Виміри | організація, контрагент, напрям `LIABILITY` (зобов'язання — видані ПН) / `CREDIT` (кредит — отримані ПН), ставка ПДВ |
| Ресурси | база (обсяг без ПДВ), сума ПДВ |
| Реєстратор | `DocTaxInvoice` — рядок руху на кожну ставку ПН |
| Представлення | `v_vat_ledger` (з номером і станом ЄРПН ПН) |

## БЛОК B. ЗВІТ (сторінка 630, `trade_tax.register_html`)

Період, організація: зведення за ставками (зобов'язання / кредит: база й ПДВ), «ПДВ до сплати» або
«до відшкодування»; кількість виданих ПН — проведено, зареєстровано, не зареєстровано, прострочено;
події першої події без ПН. Нижче — список ПН періоду (перехід у ПН) і «Події без податкової накладної»
(перехід у документ-підставу); кнопка «Створити ПН за першою подією».

## Обмеження

Податковий кредит фіксується проведенням отриманої ПН (без перевірки реєстрації постачальником в ЄРПН —
стан ведеться вручну). Декларація з ПДВ і додаток 1 — поза обсягом r5.
