# Паспорт довідника «Серії номенклатури»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-63).
- Ревізія: `r5`.
- Розділ меню (Taxi): `НСІ` → «Номенклатура»; `Склад` → «НСІ»; звіт «Товари з терміном, що
  спливає» — `Склад` / `Продажі` / `Головне` → «Звіти».
- Залежності: `RefProduct` r5 (`useSeries`, `shelfLifeDays`), `RegStockBalance`,
  `RegStockReserve`, `RegStockCost` (вимір `seriesId`), документи складу.
- Аналог у 1С:УТ 11: Справочник.СерииНоменклатуры + звіт «Контроль термінів придатності»
  (спрощено: без видів номенклатури й політик обліку серій по складах — облік серій увімкнено
  для товару на всіх складах; без ордерної схеми; FEFO — фіксоване правило).
- Функції каталогу: `F-NSI-10`.

## БЛОК B. ЛОГІКА (пакет `trade_series`, db/38)

- **Виміри регістрів.** Тригери рухів `RegStockBalance` / `RegStockReserve` / `RegStockCost`
  беруть `characteristicId` / `seriesId` з рядка документа-реєстратора (номер рядка руху
  mod 1 000 000 = номер рядка документа; товар має збігатися). Процедури проведення r1–r4 не
  змінено. Для товару з `useSeries` рух `RegStockBalance` без серії заборонено
  (`SERIES_REQUIRED`). Видатковий рух контролює залишок серії (`INSUFFICIENT_SERIES_STOCK`).
  Підсумки `*_tot` / знімки, вільний залишок (резерви) і середня ковзна собівартість — у
  розрізі склад × товар; виміри серії в резерві й собівартості аналітичні.
- **FEFO** (`fill_fefo`): рядки без серії заповнюються серіями з додатним залишком на складі
  (без рухів самого документа) у порядку «придатний до» ↑, дата виробництва ↑, номер; рядок
  ділиться на кілька рядків (ціна / інші реквізити копіюються, суми перераховуються).
  Реалізація пропускає серії, термін яких минув на дату документа; списання, переміщення й
  комплектація (комплектуючі) — ні. Команда «Підібрати серії (FEFO)» (111, 131, 141, 441)
  залишає нестачу окремим рядком без серії; проведення реалізації / переміщення / списання
  підбирає серії автоматично й при нестачі відмовляє (`SERIES_INSUFFICIENT`). Комплектація
  автоматично серії не підбирає (лише командою).
- Продаж простроченої серії, вказаної вручну, — неблокувальне попередження `SERIES_EXPIRED`.
- Повернення від клієнта / постачальнику беруть характеристику й серію з рядка-підстави.
- Ознаки `useCharacteristics` / `useSeries` змінюються лише за нульового залишку товару на всіх
  складах (`SERIES_FLAGS_WITH_STOCK`); послуги не мають ознак.
- **Звіт 510** «Товари з терміном, що спливає» (`v_series_stock_balance`): на дату, «спливає
  протягом N днів» (типово 30; порожньо — усі залишки серій і характеристик), склад; стан
  «Прострочено» / «Термін спливає», днів до закінчення, оцінка собівартості (середня × кількість).

## Відхилення / межі r5

- Друковані форми не показують характеристику / серію.
- Інвентаризація рахує залишки в розрізі товару; оприбуткування надлишків і списання на її
  підставі потребують серії / характеристики в рядках (списання — FEFO).
- Набір у комплектації не може бути товаром з характеристиками / серіями (рух набору не має
  рядка документа).
