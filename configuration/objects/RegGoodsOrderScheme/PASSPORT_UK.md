# Паспорт регістрів «Товари до надходження / до відвантаження» і «Товари в комірках»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем (APE-65).
- Ревізія: `r5`.
- Вид: `BALANCE` (накопичувальні регістри залишків).
- Розділ меню (Taxi): `Склад` → «Ордерний склад» → «Товари до надходження й відвантаження» (сторінка 580, усі ролі).
- Аналог у 1С:УТ 11: РегистрНакопления.ТоварыКПоступлению / ТоварыКОтгрузке (+ ТоварыНаСкладах як
  фактичний залишок) і ТоварыВЯчейках. Спрощено: одна таблиця для обох напрямів, без графіка й дат
  відвантаження.
- Функції каталогу: `F-WH-11`; основа для `F-WH-12`…`F-WH-15` (APE-278/280/282/284).

## БЛОК A. СТРУКТУРА

### 1. RegGoodsOrderScheme — `reg_goods_order_mv`

| Поле | Роль | Правила |
|---|---|---|
| `period`, `recorderType`, `recorderId`, `lineNumber` | системні | UNIQUE (реєстратор, рядок) |
| `direction` | вимір | `RECEIPT` — до надходження, `SHIPMENT` — до відвантаження |
| `warehouseId` | вимір | лише склади з ордерною схемою |
| `basisType`, `basisId` | вимір | розпорядження — документ менеджера (для руху документа менеджера = він сам) |
| `productId`, `characteristicId`, `seriesId` | виміри | з руху `RegStockBalance` (виміри r5 F-NSI-10) |
| `quantity` | ресурс | документ менеджера +кількість; ордер −кількість; залишок = ще не оформлено ордерами |

Записи документів менеджера формуються **тригером** `reg_stock_balance_mv_ord` з рухів
`RegStockBalance` ордерного складу (прихід → `RECEIPT`, розхід → `SHIPMENT`), тому пакети
проведення r1–r5 не змінено. Без рухів: інвентаризація, оприбуткування надлишків і списання на
підставі інвентаризації (фактичний стан). Видалення рухів документа (скасування / повторне
проведення), за яким проведено ордери на цьому складі, заборонене — `ORDER_BASIS_HAS_ORDERS`.

### 2. RegBinStock — `reg_bin_stock_mv`

| Поле | Роль | Правила |
|---|---|---|
| `warehouseId`, `binId`, `productId`, `characteristicId`, `seriesId` | виміри | склади з адресним зберіганням |
| `quantity` | ресурс | прибутковий ордер +, видатковий −; від'ємний залишок комірки заборонено (`BIN_STOCK_INSUFFICIENT`) |

### 3. Похідні показники

- **Фактичний залишок** ордерного складу = `RegStockBalance` − до надходження + до відвантаження
  (`trade_order_scheme.physical_qty`, `v_order_scheme_stock`); не може стати від'ємним після
  видаткового ордера або скасування прибуткового (`ORDER_PHYSICAL_STOCK`).
- **Стан розпорядження** (`v_goods_order_basis`, `basis_state`): `WAITING` — «Очікується приймання» /
  «До відбору»; `PARTIAL` — «Прийнято / Відвантажено частково»; `DONE` — «Прийнято» / «Відвантажено».
  Розпорядженням на відвантаження є проведений видатковий документ менеджера на ордерному складі.
