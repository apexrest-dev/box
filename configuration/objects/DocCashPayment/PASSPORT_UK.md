# Паспорт документа «Видатковий касовий ордер» (ВКО)

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08 (Linear APE-53), реалізовано без формального
  погодження (як r2–r4); потребує явного погодження користувача.
- Ревізія: `r4`.
- Розділ основного меню: `Документи`; панель функцій `Фінанси` (група «Каса», важливе).
- Залежності: як `DocCashReceipt`.
- Аналог у 1С:УТ 11: Документ.РасходныйКассовыйОрдер.
- Функція каталогу: `F-FIN-03`.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|
| Українська назва | Видатковий касовий ордер |
| Технічне ім'я | `DocCashPayment` |
| Технічний ключ | `Document.CashPayment` |
| Таблиця | `doc_cash_payment` (структура полів — як `doc_cash_receipt`) |
| Нумерація | `doc_cash_payment_num_seq` |
| API | `/api/v1/documents/cash-payments` |
| Сторінки APEX | 380 (список), 381 (документ); касова книга — 390 |

Поля — як у ПКО (паспорт `DocCashReceipt`, п. 2); `personName` має назву «Видати»; вид операції за
замовчуванням `SUPPLIER_PAYMENT`; банківський рахунок обов'язковий для інкасації.

### Види операцій

| Код | Назва | Каса | Інший рух |
|---|---|---|---|
| `SUPPLIER_PAYMENT` | Оплата постачальнику | − сума | `RegCounterpartySettlement` `PAYABLE` − сума |
| `CUSTOMER_REFUND` | Повернення коштів покупцю | − сума | `RegCounterpartySettlement` `RECEIVABLE` + сума |
| `ACCOUNTABLE_ISSUE` | Видача підзвітній особі | − сума | — |
| `ENCASHMENT` | Інкасація (здача готівки в банк) | − сума | `RegCashBalance` рахунок + сума (рядок 2) |
| `OTHER` | Інша видача | − сума | — |

## БЛОК B. UI

Як у ПКО. Введення на підставі (кнопка «Створити ВКО», роль «каса»): прибуткова накладна (проведена; сума —
залишок боргу постачальнику, не більше суми накладної), повернення від клієнта (будь-який стан; сума повернення).

## БЛОК C. БІЗНЕС-ЛОГІКА

- Проведення `trade_cash_doc.post_payment`: каса − сума; від'ємний залишок каси на будь-який момент заборонений
  (`CASH_BALANCE_NEGATIVE`, у т. ч. витрата заднім числом); переплата постачальнику заборонена.
- Скасування: повернення коштів покупцю не скасовується, якщо товар уже повернено й борг став би від'ємним.

## БЛОК D. ДРУК

- КО-2 «Видатковий касовий ордер»: організація, номер, дата, сума, видати, підстава, додаток, керівник, головний
  бухгалтер, «Одержав» (сума прописом), дата й підпис одержувача, документ, що посвідчує особу, «Видав касир».
- Касова книга (КО-4, сторінка 390, `trade_cash_doc.cash_book_html`): вкладний аркуш на кожен день з рухами каси
  (наскрізна нумерація аркушів від першого руху каси), залишок на початок дня, ордери (номер, від кого / кому,
  підстава), надходження / видаток, разом за день, залишок на кінець дня, кількість прибуткових і видаткових
  ордерів, підписи касира й бухгалтера.

## Рішення й відхилення

| Рішення | Пояснення |
|---|---|
| Інкасація без «грошей у дорозі» | ВКО одразу зараховує суму на рахунок організації (та сама валюта); банківська виписка (APE-54) не повинна вдруге проводити надходження інкасованої готівки — рядок виписки з видом «інкасація» посилатиметься на ВКО |
| Отримання готівки в банку | симетрично: ПКО списує з рахунку й зараховує в касу |
| Повернення коштів покупцю | `RECEIVABLE` + сума; ВКО на підставі чернетки повернення проводять до повернення товару |
| Ліміт каси | не контролюється (немає в постановці r4) |
