# Паспорт обробки «Імпорт довідників»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-69).
- Ревізія: `r5`.
- Розділ меню (Taxi): `НСІ та адміністрування` → «Сервіс»; список «Звіти».
- Залежності: `RefUnitOfMeasure`, `RefProductGroup`, `RefProduct`, `RefCounterparty`, `RegBarcode`, `RefPriceType`,
  `DocPriceSetting` (ціни записуються лише документом), `RefVatRate`.
- Аналог у 1С:УТ 11: обробки «Загрузка данных из файла» (вставка табличних даних у довідник з пошуком за
  реквізитами) і «Загрузка прайс-листа»; БСП — «Загрузка данных из внешнего файла».
- Функції каталогу: `F-SRV-06`. Імпорт документів з Excel — окрема задача APE-132.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|
| Українська назва | Імпорт довідників |
| Технічне ім'я | `DataCatalogImport` (обробка) |
| Таблиці | `sys_import_session` (сеанс), `sys_import_column` (колонки файлу й зіставлення), `sys_import_row` (рядки, дія, результат) |
| Сторінка APEX | 670 — майстер: файл і параметри → стан → зіставлення колонок → рядки файлу; історія імпорту |
| Права | «Роль: адміністратор» |

Сеанс імпорту:

| Поле | Назва | Тип | Правила |
|---|---|---|---|
| `importKind` | Що завантажувати | UNIT / GROUP / PRODUCT / COUNTERPARTY / BARCODE / PRICE | обов'язкове (`IMPORT_KIND`) |
| `importMode` | Режим | CREATE_UPDATE / CREATE_ONLY / UPDATE_ONLY | за замовчуванням CREATE_UPDATE |
| `fileName`, `fileCharset` | Файл, кодування | — | CSV / TXT / TSV / XLSX (`IMPORT_FILE_FORMAT`); UTF-8 або Windows-1251 |
| `priceType`, `priceDate` | Вид цін, дата цін | ref `RefPriceType`, Date | для цін; вид цін може бути колонкою файлу |
| `status` | Стан | LOADED → CHECKED → APPLIED | виконаний імпорт не змінюється (`IMPORT_ALREADY_APPLIED`); виконання лише після перевірки (`IMPORT_NOT_CHECKED`) |
| лічильники | Рядків / створено / оновлено / цін / пропущено / помилок | Integer | — |

Рядок файлу: номер рядка у файлі, значення (JSON-масив), текст «заголовок: значення», ключ, дія
(CREATE / UPDATE / SKIP / ERROR / PRICE), спосіб пошуку (код / артикул / штрихкод / ЄДРПОУ / скорочення /
найменування), знайдений елемент, повідомлення, результат (записано / пропущено / помилка), записаний елемент.

Поля довідників (заголовки колонок розпізнаються за назвою поля й синонімами, без урахування регістру й розділових знаків):

| Довідник | Поля |
|---|---|
| Одиниці виміру | Код, Найменування*, Скорочення, Дробова кількість |
| Групи номенклатури | Код, Найменування*, Батьківська група (код / назва), Порядок |
| Номенклатура | Код, Артикул, Найменування*, Одиниця виміру, Група, Вид номенклатури, Вага, Опис, Ставка ПДВ, Код УКТ ЗЕД, Штрихкод, Ціна, Вид цін |
| Контрагенти | Код, ЄДРПОУ / РНОКПП, Найменування*, IBAN, Платник ПДВ, ІПН |
| Штрихкоди | Штрихкод*, Код товару, Артикул, Найменування товару, Кількість в упаковці |
| Ціни номенклатури | Код товару, Артикул, Штрихкод, Найменування товару, Ціна*, Вид цін |

`*` — обов'язкове для нових елементів.

## БЛОК B. ЛОГІКА (`trade_import`, db/44)

- `load_file` — розбір `apex_data_parser` (до 10 000 рядків, 60 колонок; перший рядок — заголовки, порожні рядки
  пропускаються; помилки `IMPORT_FILE_EMPTY`, `IMPORT_FILE_PARSE`, `IMPORT_FILE_NO_HEADER`, `IMPORT_FILE_NO_ROWS`,
  `IMPORT_FILE_TOO_BIG`), автоматичне зіставлення `auto_map` (точна назва поля, далі синонім; кожне поле — одна колонка).
- `set_mapping` — ручне зіставлення (`IMPORT_FIELD_UNKNOWN`); перевірка зіставлення: поле в кількох колонках
  (`IMPORT_MAPPING_DUPLICATE`), немає ключових колонок (`IMPORT_MAPPING_REQUIRED`).
- `check_rows` — попередній перегляд без запису: для кожного рядка пошук існуючого, перевірка значень (числа з
  комою / пробілами, Так / Ні, вид, ставка ПДВ 20 / 7 / 0 / «звільнено» / «без ПДВ», одиниця, група, вид цін),
  дія за режимом (не знайдено в «лише оновлювати» / знайдено в «лише створювати» — пропуск), дублікати ключа у файлі.
- Пошук: номенклатура — код → артикул → штрихкод (різні збіги — помилка); контрагенти — код → ЄДРПОУ (5–7 цифр
  доповнюються нулями попереду, кілька контрагентів з тим самим ЄДРПОУ — помилка); одиниці — код → скорочення →
  назва; групи — код → назва серед груп того самого батька (батько може бути створений попереднім рядком);
  товар у штрихкодах і цінах — код → артикул → штрихкод → однозначна назва.
- `apply` — повторна перевірка й запис кожного рядка в окремій точці збереження: помилки тригерів довідника
  (код, ЄДРПОУ, IBAN, ІПН, штрихкод EAN-13 тощо) стають помилкою рядка, інші рядки записуються. Порожня клітинка
  під час оновлення не змінює значення; код знайденого за іншим ключем елемента не змінюється; невідома група
  номенклатури (за назвою) створюється; штрихкод номенклатури додається, якщо вільний. Ціни (з файлу номенклатури
  або цін) — документ «Встановлення цін» на кожен вид цін (дата з параметрів або поточна), проводиться; помилка
  документа позначає його рядки. Журнал `sys_audit_log`: `IMPORT_LOAD`, `IMPORT` (підсумки); зміни довідників —
  тригерами журналу реєстрації.
- `errors_csv` / `download_errors` — звіт помилок і пропусків (рядок, дія, результат, ключ, повідомлення, дані);
  `template_csv` / `download_template` — шаблон із заголовками полів (UTF-8 з BOM, роздільник «;»).

## БЛОК C. UI

Сторінка 670: «1. Файл і параметри» (довідник, режим, кодування, вид і дата цін, файл; «Завантажити й перевірити»,
«Шаблон CSV», «Новий імпорт»), «Колонки файлу» (опис полів до завантаження), «2. Стан імпорту» (лічильники дій,
документи цін; «Виконати імпорт», «Звіт помилок (CSV)»), «3. Зіставлення колонок» (колонка файлу, приклад
значення, поле довідника; «Перевірити»), «4. Рядки файлу» (IR: дія, ключ, знайдено за, результат, повідомлення,
дані рядка — з відборами й вивантаженням), «Історія імпорту» (відкрити попередній сеанс).
