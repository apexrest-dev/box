# Паспорт регістру відомостей «Ціни постачальників»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем.
- Ревізія: `r3`.
- Вид: інформаційний регістр, `PERIODIC` (гранулярність — секунда), `RECORDER_MANAGED`.
- Розділ меню («Такси»): підсистема `Закупівлі` → група «Звіти»; дублюється в
  `Ціноутворення` → «Звіти».
- Реєстратор: `DocGoodsReceipt` r3 (єдиний).
- Аналог 1С:УТ 11: `РегистрСведений.ЦеныНоменклатурыПоставщиков` (спрощено: без виду цін
  постачальника, без характеристик і упаковок, лише UAH).
- Функції каталогу: `F-PRC-04`, `F-PUR-01` (автопідстановка ціни в замовлення
  постачальнику), `F-PUR-02`, `F-PUR-06` (ціна в «Потребі в закупівлі»).

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Українська назва | Ціни постачальників |
| Технічне ім'я | `RegSupplierPrice` |
| Об'єкт метаданих | `Register.SupplierPrice` (kind `INFORMATION_REGISTER`) |
| Клас запису | `SupplierPriceRecord` |
| Таблиця | `reg_supplier_price` |
| Похідні таблиці | немає (зріз останніх рахується запитом за індексом) |
| API | `/api/v1/registers/supplier-prices` |
| Сторінка APEX | 200 |

Регістр автоматично накопичує історію закупівельних цін: кожне проведене надходження
фіксує, за якою ціною товар куплено в постачальника на дату надходження. Ручного введення
немає — ціна постачальника завжди підтверджена документом.

### 2. Структура запису

| Поле | Роль | Тип | Точність | Джерело | Посилання/БД |
|---|---|---|---|---|---|
| `id` | системне | UUID | 32 hex | server | PK |
| `period` | системне (період) | DateTime UTC | секунди | `DocGoodsReceipt.occurredAt` | index |
| `recorderType` | системне | String | 60 | `'DocGoodsReceipt'` | — |
| `recorderId` | системне | UUID | — | `header.id` | index |
| `lineNumber` | системне | int | 10 | `min(Goods.lineNumber)` товару | UK з recorder |
| `supplierId` | вимір | UUID | — | `header.supplierId` | `RefCounterparty`, FK |
| `productId` | вимір | UUID | — | група рядків | `RefProduct`, FK |
| `price` | ресурс | Number | 19,2 | середньозважена ціна (п. 6) | `>= 0`, UAH за одиницю товару |

- Валюта — фіксована `UAH` (r3); окремого виміру `currencyCode` немає, з'явиться в r4 разом
  з мультивалютністю.
- Унікальність: `recorderType + recorderId + lineNumber` і додатково `recorderId +
  supplierId + productId` (один запис на товар у документі).
- Бізнес-ключ зрізу: `supplierId + productId + period`; кілька записів з однаковим
  ключем і моментом допустимі (різні надходження в одну секунду) — див. пріоритет.

### 3. Правила зрізу

- `latestAt(supplierId, productId, at)`: запис з максимальним `period <= at` (межа
  **включна**); якщо записів немає — `null` (ціна не підставляється).
- Пріоритет записів в один момент: `period DESC, doc_goods_receipt.doc_number DESC,
  recorder_id DESC` — детерміновано; пізніше введений документ (більший номер) перемагає.
- Часова зона: `period` зберігається як дата-час сервера БД (як `occurred_at` документів
  r1/r2); фільтри UI перетворюються в той самий час без зсуву.
- Фолбек на інших постачальників або на `RegProductPrice` **не** виконується: ціна
  закупівлі в чужого постачальника не є ціною цього постачальника.
- Зріз «Діючі ціни» на дату `at` — `latestAt` для всіх пар, що мають записи `<= at`.
- Видалення/архівація: записи живуть рівно стільки, скільки проведене надходження;
  скасування проведення видаляє їх, і зріз автоматично повертається до попередньої ціни.

## БЛОК B. UI

### 4. Форма списку (сторінка 200, read-only)

1. **Діючі ціни** (за замовчуванням, станом на зараз): `supplier[25] | product[35] |
   unit[8] | price[12] «Ціна, UAH» | period[16] «Дата ціни» | recorder[25] «Документ»`.
   Групування за постачальником (або за товаром — перемикач «Порівняти постачальників»:
   групування товар → постачальник, мінімальна ціна в групі виділена жирним).
2. **Історія**: `period[16] | recorder[25] | supplier[25] | product[35] | price[12] |
   change[10] «Зміна, %»` (до попереднього запису тієї ж пари; перший — порожньо).

Фільтри: «станом на» (Діючі ціни), період `[from, to]` включно (Історія, за замовчуванням
останні 90 днів), постачальник, товар, група товарів (`RefProductGroup`, з підгрупами).
Подвійний клік / Enter по рядку відкриває надходження-реєстратор. Експорт IR (CSV/XLSX).
Кнопок «Створити/Змінити/Видалити» немає. Обов'язкові колонки `period` і `recorder`
(`SYSTEM_FIELDS_UK.md` п. 7).

### 5. Події введення

Поля записів `DISABLED`. Фільтри — стандартний `INPUT_STARTED/INPUT_COMMITTED`, commit
перезапускає `QuerySupplierPrices`.

## БЛОК C. БІЗНЕС-ЛОГІКА

### 6. Розрахунки

**Вибір: середньозважена ціна за документом, а не ціна останнього рядка.**

```text
price(supplier, product, receipt) = round(Σ Goods.amount / Σ Goods.quantity, 2, HALF_UP)
                                    за рядками товару в надходженні
якщо Σ Goods.amount = 0 (увесь товар отримано безкоштовно) — запис не формується
```

Обґрунтування:

- не залежить від порядку рядків — переміщення рядка в документі не змінює «ціну
  постачальника»;
- коректно враховує бонусні/безкоштовні рядки (ціна 0): ефективна ціна закупівлі знижується,
  а не стає нулем (як було б, якщо бонус — останній рядок);
- узгоджена з `RegStockCost` (середня ковзна) — у звіті валового прибутку не буде
  розбіжностей «ціна постачальника vs собівартість приходу»;
- у типовому випадку (один рядок товару) дорівнює ціні рядка.

Приклади:

| № | Рядки товару в надходженні | Розрахунок | `price` |
|---|---|---|---|
| 1 | 10 × 25,00 | 250,00 / 10 | 25,00 |
| 2 | 10 × 25,00 + 2 × 0,00 (бонус) | 250,00 / 12 = 20,8333 | 20,83 |
| 3 | 3 × 10,00 + 1 × 10,01 | 40,01 / 4 = 10,0025 | 10,00 |
| 4 | 2,500 кг × 12,34 (=30,85) + 1,000 × 12,40 | 43,25 / 3,5 = 12,357 | 12,36 |
| 5 | 5 × 0,00 | Σ amount = 0 | запису немає |

Приклад зрізу. Постачальник «Альфа», товар «Кабель»: Н-1 від 01.11 10:00 — 20,00;
Н-2 від 05.11 09:00 — 21,50. `latestAt(05.11 08:59:59) = 20,00`,
`latestAt(05.11 09:00:00) = 21,50` (межа включна). Скасування Н-2 → `latestAt(зараз) = 20,00`.

**Автопідстановка в `DocSupplierOrder`** (F-PUR-01): при додаванні/зміні товару в рядку з
порожньою ціною сервер виконує `latestAt(header.supplierId, productId, header.occurredAt)`;
якщо `null` — ціна лишається порожньою, рядок не записується без ціни (повідомлення
замовлення). Зміна постачальника в шапці не перезаписує вже введені ціни; команда
«Оновити ціни постачальника» перезаповнює всі рядки. Ціна з регістру — пропозиція,
користувач може змінити.

### 7. Формування записів

**DocGoodsReceipt r3** (`recorderType = 'DocGoodsReceipt'`), рядки групуються за `productId`
(послуги включаються — ціна послуги постачальника теж корисна):

| Поле | Джерело | Умова |
|---|---|---|
| `period` | `header.occurredAt` | — |
| `supplierId` | `header.supplierId` | — |
| `productId` | група рядків | — |
| `price` | `round(Σ amount / Σ quantity, 2)` | `Σ amount > 0` |
| `lineNumber` | `min(Goods.lineNumber)` групи | — |

Незалежно від `baseOrderId` (ціна фіксується і для надходжень без замовлення).

- Повторне проведення: `delete from reg_supplier_price where recorder_type/id = ...` →
  `insert`; та сама транзакція, що й рухи `RegStockBalance`/`RegCounterpartySettlement`.
- Скасування проведення: видалення набору.
- Перевірки в транзакції: `SUPPLIER_PRICE_NEGATIVE` («Ціна постачальника не може бути
  від'ємною.») — захисна, бо `price >= 0` у рядках; FK на неактивні довідники не
  перевіряються повторно (перевіряє сам документ).
- Lock: окремого не потрібно (немає інваріанта між документами); порядок `period`
  детермінований пріоритетом п. 3.

### 8. Зберігання, запити й API

```text
reg_supplier_price
  id            varchar2(32)  default rawtohex(sys_guid()) PK
  period        date          NOT NULL
  recorder_type varchar2(60)  NOT NULL CHECK (= 'DocGoodsReceipt')
  recorder_id   varchar2(32)  NOT NULL
  line_number   number(10)    NOT NULL
  supplier_id   varchar2(32)  NOT NULL FK ref_counterparty
  product_id    varchar2(32)  NOT NULL FK ref_product
  price         number(19,2)  NOT NULL CHECK (price >= 0)
  UK reg_supplier_price_rec_uk (recorder_type, recorder_id, line_number)
  UK reg_supplier_price_doc_uk (recorder_id, supplier_id, product_id)
  IX reg_supplier_price_key_ix (supplier_id, product_id, period)
  IX reg_supplier_price_prd_ix (product_id, period)
```

Тригер `reg_supplier_price_biud` (як `reg_product_price_biud`) — DML лише при
`trade_core.g_internal`. Функція `trade_lines.get_supplier_price(p_supplier_id,
p_product_id, p_date) return number` — аналог `get_price`.

Queries: `QuerySupplierPrices(mode = CURRENT|HISTORY, at | from..to, filters, sort, page)`,
`GetSupplierPriceLatestAt(supplierId, productId, at)`, `GetSupplierPricesForProducts(
supplierId, productIds[], at)` (пакетна автопідстановка), `CompareSupplierPrices(productId,
at)`. Стабільне сортування історії: `period DESC, doc_number DESC, id`. Права: `read`
(закупівельник, менеджер, адміністратор); запису через API немає.

### 9. Тести й готовність

1. Один рядок → запис із ціною рядка; приклади 2–5 з таблиці п. 6.
2. `latestAt` на межі (рівно `period`) і на секунду раніше.
3. Два надходження в одну секунду → перемагає більший номер.
4. Повторне проведення зі зміненою ціною замінює запис, не дублює.
5. Скасування проведення повертає попередню ціну в зрізі.
6. Автопідстановка в замовлення постачальнику: є ціна / немає ціни / зміна постачальника.
7. Прямий `insert` відхиляється тригером; сторінка 200 read-only; експорт.
