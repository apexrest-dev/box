# Паспорт документа «Банківська виписка»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08 (Linear APE-54), реалізовано без формального
  погодження (як r2–r4); потребує явного погодження користувача.
- Ревізія: `r4`.
- Розділ основного меню: `Документи`; панель функцій `Фінанси` (група «Банк», важливе).
- Залежності: `RefOrganization`, `RefBankAccount`, `RefCounterparty` (реквізити ЄДРПОУ / IBAN), `RefContract`,
  `RegCashBalance`, `RegCounterpartySettlement`, `DocCashReceipt` / `DocCashPayment` (готівкові операції).
- Логіка — пакет `trade_bank_doc`.
- Аналог у 1С:УТ 11: Документи.ПоступлениеБезналичныхДенежныхСредств / СписаниеБезналичныхДенежныхСредств,
  обробка «Клієнт банку» (тут — один документ-виписка з табличною частиною операцій).
- Функція каталогу: `F-FIN-04`. Імпорт файлів клієнт-банку — APE-185.

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Українська назва | Банківська виписка |
| Технічне ім'я | `DocBankStatement` |
| Технічний ключ | `Document.BankStatement` |
| Таблиці | `doc_bank_statement` (шапка), `doc_bank_statement_line` (операції); список `v_bank_statement_list` |
| Нумерація | `doc_bank_statement_num_seq`, 9 символів, без перевикористання; ручний номер 1–9 символів |
| API | `/api/v1/documents/bank-statements` |
| Сторінки APEX | 400 (список), 401 (документ) |

Відображає рух безготівкових коштів на банківському рахунку організації за день: надходження та списання.

### 4. Види операцій

| Код | Назва | Напрям | Рахунок | Взаєморозрахунки |
|---|---|---|---|---|
| `CUSTOMER_PAYMENT` | Оплата від покупця | IN | + сума | `RECEIVABLE` − сума |
| `SUPPLIER_REFUND` | Повернення коштів постачальником | IN | + сума | `PAYABLE` + сума |
| `CASH_DEPOSIT` | Внесення готівки (інкасація) | IN | — (рух робить ВКО) | — |
| `OTHER_IN` | Інше надходження | IN | + сума | — (контрагент необов'язковий) |
| `SUPPLIER_PAYMENT` | Оплата постачальнику | OUT | − сума | `PAYABLE` − сума |
| `CUSTOMER_REFUND` | Повернення коштів покупцю | OUT | − сума | `RECEIVABLE` + сума |
| `CASH_WITHDRAWAL` | Зняття готівки в касу | OUT | — (рух робить ПКО) | — |
| `BANK_FEE` | Банківська комісія | OUT | − сума | — |
| `OTHER_OUT` | Інше списання | OUT | − сума | — |

Операції з контрагентом — лише на гривневому рахунку (`BANK_SETTLEMENT_CURRENCY`).

### 5. Готівкові операції (правило «без подвійного руху»)

ВКО «Інкасація» і ПКО «Отримання готівки в банку» (DocCashPayment / DocCashReceipt, APE-53) уже рухають і касу, і
рахунок. Рядок виписки `CASH_DEPOSIT` / `CASH_WITHDRAWAL` лише звіряє банк з ордером:

- рядку вказують ордер вручну або командою «Підібрати касові ордери» / автоматично при проведенні — проведений ордер
  того самого рахунку, на ту саму суму, з датою ±3 дні від виписки, ще не прив'язаний;
- перевірки: вид ордера (`BANK_CASH_ORDER_KIND`), рахунок (`BANK_CASH_ORDER_ACCOUNT`), сума (`BANK_CASH_ORDER_AMOUNT`);
  при проведенні ордер обов'язковий (`BANK_CASH_ORDER_REQUIRED`) і проведений (`BANK_CASH_ORDER_NOT_POSTED`);
- рух `RegCashBalance` для такого рядка не пишеться;
- ордер, прив'язаний до проведеної виписки, не можна скасувати, а прив'язаний до будь-якої виписки — видалити
  (`BANK_CASH_ORDER_LINKED`).

### 6. Автопошук контрагента

`trade_bank_doc.find_counterparty`: 1) `ref_counterparty.edrpou` = ЄДРПОУ з виписки; 2) `ref_counterparty.iban`
= IBAN; 3) контрагент, указаний для цього IBAN у попередніх виписках. Лише однозначний активний збіг. Кроки 1–2
виконує тригер рядка (запис вручну), усі три — команда «Заповнити контрагентів» і API імпорту `add_line`.
Якщо контрагента змінено вручну, позначка «Знайдено за» скидається.

### 7. Статуси й команди

`DRAFT → POSTED` (Провести), `POSTED → DRAFT` (Скасувати проведення); проведений документ і рядки лише для читання
(`DOCUMENT_READ_ONLY`), не видаляється (`DOCUMENT_POSTED`); чернетка видаляється разом з рядками. «Скопіювати (F9)»
— нова чернетка з рядками без касових ордерів. «Заповнити контрагентів», «Підібрати касові ордери» — для чернетки.

## БЛОК C. БІЗНЕС-ЛОГІКА

- Проведення (`trade_bank_doc.post`): автозв'язок готівкових рядків з ордерами; перевірки рядків (вище); атомарна
  заміна рухів реєстратора; `trade_cash.add_movement` (рахунок, рядок = рядок виписки); рух взаєморозрахунків
  з організацією виписки; `trade_cash.check_balances` (`BANK_BALANCE_NEGATIVE` на будь-який момент);
  `trade_org.check_settlement` для кожного контрагента (переплата заборонена `SETTLEMENT_NEGATIVE_BY_ORGANIZATION`);
  порожня виписка — `BANK_NO_LINES`.
- Скасування проведення: видалення рухів і повторні перевірки (не можна скасувати надходження, якщо гроші вже
  списано; повернення коштів — якщо борг уже погашено).
- Залишок рахунку на початок / кінець дня — `opening_balance` / `closing_balance`.
- API імпорту (APE-185): `trade_bank_doc.add_line(doc, direction, amount, purpose, cp_name, cp_edrpou, cp_iban,
  ext_number, ext_date, operation_kind)`; дубль (рахунок + № + дата платіжки + сума + напрям) не додається
  (повертає null). Імпорт заповнює `source_format` / `source_name` під час створення виписки.
- Аудит POST / UNPOST / COPY / FILL_COUNTERPARTIES.

## Рішення й відхилення

| Рішення | Пояснення |
|---|---|
| Один документ замість двох 1С | надходження й списання — рядки однієї виписки за день; кожен рядок — окремий рух |
| Готівка проводиться касовим ордером | інкасація / зняття готівки рухають касу й рахунок одним ордером (APE-53); виписка їх лише звіряє |
| Контрагент у чернетці необов'язковий | щоб зберегти імпортовані рядки без збігу; обов'язковий при проведенні |
| Банківські рахунки контрагентів | окремого довідника немає — основний IBAN у картці + історія виписок |
| Аванси / переплата | заборонені до APE-55/57 |
| Статті руху коштів | довідника немає; вид операції й зміст руху |
| Без друкованої форми | виписку друкує банк; звіт «Залишки й обороти коштів» (360) показує рухи |


## Доповнення r4 F-PUR-05 (APE-56): прив'язка рядків до документів оплати

Правило одного платежу (паспорт `DocSupplierPayment`, R4.3): рядок «Оплата постачальнику», прив'язаний до
безготівкової оплати, не рухає рахунок і взаєморозрахунки — їх уже записала оплата. Проведення виписки
автоматично прив'язує такі рядки (рахунок, контрагент, сума, ±3 дні; спершу — номер платіжки = номер оплати),
команда «Підібрати оплати» робить те саме для чернетки. Неприв'язаний рядок проводить сама виписка, і тоді
оформити той самий платіж документом оплати не можна (`PAYMENT_ALREADY_IN_STATEMENT`).
