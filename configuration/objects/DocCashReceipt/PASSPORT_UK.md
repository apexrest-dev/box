# Паспорт документа «Прибутковий касовий ордер» (ПКО)

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08 (Linear APE-53), реалізовано без формального
  погодження (як r2–r4); потребує явного погодження користувача.
- Ревізія: `r4`.
- Розділ основного меню: `Документи`; панель функцій `Фінанси` (група «Каса», важливе).
- Залежності: `RefOrganization`, `RefCashDesk`, `RefBankAccount`, `RefCounterparty`, `RefContract`,
  `RegCashBalance`, `RegCounterpartySettlement`.
- Парний документ: `DocCashPayment` (ВКО). Спільна логіка — пакет `trade_cash_doc`.
- Аналог у 1С:УТ 11: Документ.ПриходныйКассовыйОрдер.
- Функція каталогу: `F-FIN-03`.

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Українська назва | Прибутковий касовий ордер |
| Технічне ім'я | `DocCashReceipt` |
| Технічний ключ | `Document.CashReceipt` |
| Таблиця | `doc_cash_receipt` (спільне представлення `v_cash_order`, список `v_cash_order_list`) |
| Нумерація | `doc_cash_receipt_num_seq`, 9 символів, без перевикористання; ручний номер 1–9 символів |
| API | `/api/v1/documents/cash-receipts` |
| Сторінки APEX | 370 (список), 371 (документ) |

Оформлює надходження готівки в касу організації.

### 2. Поля шапки

| Поле | Назва | Тип | Обов'язкове | Правило |
|---|---|---|---|---|
| `docNumber`, `occurredAt` | Номер, дата | — | так | як у всіх документах |
| `organizationId` | Організація | `RefOrganization` | так | = організація каси; порожнє → з каси; інша → `CASH_DESK_ORGANIZATION` |
| `operationKind` | Вид операції | enum | так | див. п. 3; за замовчуванням `CUSTOMER_PAYMENT` |
| `cashDeskId` | Каса | `RefCashDesk` | так | активна; список — каси організації |
| `currencyCode` | Валюта | String(3) | так | з каси (лише читання) |
| `amount` | Сума | BigDecimal(19,2) | так | > 0 (`CASH_AMOUNT`) |
| `counterpartyId` | Контрагент | `RefCounterparty` | для операцій з контрагентом | `CASH_COUNTERPARTY_REQUIRED`; для «Інше надходження» — необов'язковий, без взаєморозрахунків |
| `contractId` | Договір | `RefContract` | ні | вид договору за операцією; один договір — підставляється |
| `accountablePerson` | Підзвітна особа | String(255) | для «Повернення від підзвітної особи» | `CASH_ACCOUNTABLE_REQUIRED` |
| `bankAccountId` | Банківський рахунок | `RefBankAccount` | для «Отримання готівки в банку» | та сама організація (`CASH_BANK_ORGANIZATION`) і валюта (`CASH_BANK_CURRENCY`) |
| `personName` | Прийнято від | String(255) | ні | порожнє → контрагент / підзвітна особа / банк |
| `basis` | Підстава | String(500) | ні | порожнє → «вид операції за документом-підставою» |
| `appendix` | Додаток | String(500) | ні | для КО-1 |
| `baseDocType` / `baseDocId` | Документ-підстава | посилання | ні | організація й контрагент підстави мають збігатися (`CASH_BASE_ORGANIZATION`, `CASH_BASE_COUNTERPARTY`) |
| `docComment`, `status`, `version`, аудит | — | — | — | як у всіх документах |

Поля, що не стосуються виду операції, очищаються сервером і ховаються у формі.

### 3. Види операцій

| Код | Назва | Каса | Інший рух |
|---|---|---|---|
| `CUSTOMER_PAYMENT` | Оплата від покупця | + сума | `RegCounterpartySettlement` `RECEIVABLE` − сума |
| `SUPPLIER_REFUND` | Повернення коштів постачальником | + сума | `RegCounterpartySettlement` `PAYABLE` + сума |
| `ACCOUNTABLE_RETURN` | Повернення від підзвітної особи | + сума | — (розрахунки з підзвітними — поза r4) |
| `BANK_WITHDRAWAL` | Отримання готівки в банку | + сума | `RegCashBalance` рахунок − сума (рядок 2) |
| `OTHER` | Інше надходження | + сума | — |

Розрахунки з контрагентами — лише в UAH (`CASH_SETTLEMENT_CURRENCY`); інші операції — у валюті каси.

### 4. Статуси й команди

`DRAFT → POSTED` (Провести), `POSTED → DRAFT` (Скасувати проведення); проведений документ лише для читання
(`DOCUMENT_READ_ONLY`) і не видаляється (`DOCUMENT_POSTED`); чернетку можна видалити фізично.
«Скопіювати (F9)» — нова чернетка з тими самими реквізитами.

## БЛОК B. UI

- Список (370): Номер, Дата, Організація, Вид операції, Каса, Контрагент, Прийнято від, Сума, Валюта, Статус, Коментар.
- Документ (371): `Організація | Вид операції`, `Каса | Валюта | Сума`, `Контрагент | Договір`, `Підзвітна особа |
  Банківський рахунок`, `Прийнято від | Підстава`, `Додаток | Документ-підстава`, коментар. Команди стандартні +
  «Друк» (форма КО-1, сторінка 900).
- Сторінки й команди — схема «Роль: каса» (Адміністратор, Касир).
- Введення на підставі (кнопка «Створити ПКО» лише для ролі «каса»): реалізація (проведена; сума — залишок боргу
  покупця, не більше суми накладної), рахунок на оплату (виданий; сума рахунку), повернення постачальнику
  (будь-який стан; сума повернення). Каса — перша активна гривнева каса організації підстави.

## БЛОК C. БІЗНЕС-ЛОГІКА

- Проведення (`trade_cash_doc.post_receipt`): атомарна заміна рухів реєстратора; `trade_cash.add_movement` (каса,
  рядок 1; для `BANK_WITHDRAWAL` — рахунок, рядок 2); рух взаєморозрахунків з організацією документа;
  `trade_cash.check_balances` (від'ємний залишок рахунку на будь-який момент — `BANK_BALANCE_NEGATIVE`);
  `trade_org.check_settlement` — переплата (від'ємна заборгованість) заборонена `SETTLEMENT_NEGATIVE_BY_ORGANIZATION`.
- Скасування проведення: видалення рухів, повторні перевірки (не можна скасувати ПКО, якщо гроші вже видано —
  `CASH_BALANCE_NEGATIVE`; повернення коштів постачальником — якщо товар уже повернено).
- Аудит POST / UNPOST / COPY / CREATE_BASED_ON / PRINT.

## БЛОК D. ДРУК

- КО-1 «Прибутковий касовий ордер» з квитанцією (відривна частина): організація, ЄДРПОУ, номер, дата, сума,
  прийнято від, підстава, сума прописом (UAH), додаток, головний бухгалтер, касир (відповідальний каси).
- Касова книга (КО-4, сторінка 390) — див. паспорт `DocCashPayment`.

## Рішення й відхилення

| Рішення | Пояснення |
|---|---|
| ПКО від покупця рухає взаєморозрахунки | як `DocCustomerPayment` r2; r2-оплата лишається «без джерела коштів» до APE-56/57 (туди додасться вибір каси / рахунку) — одну оплату не оформлюють обома документами |
| Аванси (переплата) заборонені | як у r1–r3; ПКО за рахунком до відвантаження не проводиться — до APE-55/57 (аванси, коригування боргу) |
| Повернення коштів постачальником | `PAYABLE` + сума: проводиться до повернення товару (повернення товару не може зробити борг від'ємним) |
| Без кореспондуючих рахунків | бухгалтерського плану рахунків немає; графи КО-1 лишаються порожніми |
| Підзвітна особа — текст | довідника фізосіб і регістру розрахунків з підзвітними немає |
