# Паспорт довідника «Валюти»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-66).
- Ревізія: `r5`.
- Розділ меню (Taxi): `Фінанси` → «Казначейство»; `НСІ та адміністрування` → «Підприємство».
- Залежності: `RegCurrencyRate` (курси); посилаються за кодом: `RefCashDesk`, `RefBankAccount`, `RefContract`,
  `RefPriceType`, `DocCashReceipt`, `DocCashPayment`, `DocBankStatement`, `RegCashBalance`,
  `RegCounterpartySettlement`.
- Аналог у 1С:УТ 11: Справочник.Валюты (спрощено: без параметрів прописом, способу встановлення курсу
  «націнка на курс іншої валюти» і формули).
- Функції каталогу: `F-FIN-06`.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|
| Українська назва | Валюти (елемент — «Валюта») |
| Технічне ім'я | `RefCurrency` |
| Таблиця | `ref_currency` |
| Сторінки APEX | 600 — список, 601 — картка (модальний діалог) |
| Права | перегляд — усі ролі; запис / помітка — «Роль: каса» (Адміністратор, Касир) |
| Вид видалення | `MARK_FOR_DELETION` (`trade_core.catalog_table` + `REF_CURRENCY`) |

| Поле | Назва | Тип | Обов'язкове | Правила |
|---|---|---|---|---|
| `code` | Код ISO 4217 | String(3) | так | 3 латинські літери, верхній регістр (`CURRENCY_CODE`); UNIQUE — **ключ посилань**; код, що вже використовується, не змінюється (`CURRENCY_IN_USE`) |
| `numericCode` | Цифровий код | String(3) | ні | 3 цифри (`CURRENCY_NUMERIC_CODE`), доповнюється нулями; UNIQUE; = `r030` НБУ |
| `name` | Найменування | String(100) | так | `CURRENCY_NAME` |
| `symbol` | Символ | String(10) | ні | ₴, $, € |
| `loadRates` | Завантажувати курс НБУ | Boolean | так | для UAH завжди «Ні» |
| `note` | Коментар | String(1000) | ні | — |
| `state`, `version`, аудит | — | — | — | стандартні |

Початкові дані: UAH (національна), USD, EUR, PLN, GBP (з ознакою «Завантажувати курс НБУ»).

### Рішення: код ISO як ключ

Поля `currency_code` r1–r4 лишаються літерними кодами — без міграції на `id`. На них створено зовнішні ключі
`→ ref_currency(code)` (10 FK разом із `reg_currency_rate`). `trade_fin.check_currency` (тригери кас і рахунків)
додатково перевіряє, що валюта є в довіднику й активна (`CURRENCY_UNKNOWN` / `CURRENCY_INACTIVE`).
Список вибору `currencies` читає довідник (раніше — статичний список).

## БЛОК B. ЛОГІКА Й UI

- Тригер `ref_currency_biu` → `trade_currency.check_currency`; фізичне видалення заборонене.
- Національна валюта — UAH (`trade_currency.c_national`): курс 1, не помічається на видалення, код не змінюється
  (`CURRENCY_NATIONAL`).
- Список 600 (`v_currency_list`): код, цифровий код, символ, ознака НБУ, курс на сьогодні й дата курсу,
  кількість записів курсу.

## БЛОК C. ОБМЕЖЕННЯ r5 (обсяг APE-66)

- Документи й взаєморозрахунки — **лише в UAH** (check-обмеження `*_cur_ck` r1–r4 не знято); валютні каси й
  рахунки працюють в своїй валюті тільки для операцій без контрагента (інше надходження / списання,
  внутрішні переміщення).
- Не реалізовано (наступний етап F-FIN-06 / F-FIN-16): валюта договору й документа з перерахунком у гривню при
  проведенні, вимір валюти й гривневої суми в `RegCounterpartySettlement`, курсові різниці (переоцінка
  взаєморозрахунків і валютних залишків).
- Гривневий еквівалент — у звітах: залишки й обороти коштів (сторінка 360, `v_cash_balance_uah`).
