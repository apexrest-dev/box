# Паспорт документа «Податкова накладна»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-67).
- Ревізія: `r5` (F-TAX-01). Розрахунок коригування — APE-302; обмін з ЄРПН через M.E.Doc / Вчасно
  (КЕП, відправлення, квитанції) — APE-306; електронні первинні документи — APE-316.
- Розділ меню (Taxi): `Фінанси` → група «ПДВ»; також `Продажі` → «Розрахунки з клієнтами»,
  `Закупівлі` → «Розрахунки з постачальниками».
- Залежності: `RefOrganization` (платник ПДВ, ІПН), `RefCounterparty` (платник ПДВ, ІПН),
  `RefProduct` (ставка ПДВ, код УКТ ЗЕД), `RefVatRate`, `RegCounterpartySettlement` (оплати для
  правила першої події), `DocGoodsSale`, `DocCustomerPayment`, `DocCashReceipt`, `DocBankStatement`,
  `DocGoodsReceipt`; рухи — `RegVatLedger`.
- Аналог у 1С:УТ 11 (українська редакція): Документ.НалоговаяНакладная (видана) і
  Документ.НалоговаяНакладнаяПолученная; «Реєстр податкових накладних».
- Функції каталогу: `F-TAX-01`.

| `status` | Статус | DRAFT / POSTED | |

Рядки: товар (необов'язковий), опис постачання, код УКТ ЗЕД / ДКПП, одиниця, кількість, ціна без
ПДВ, ставка (не «Без ПДВ» — `TAX_LINE_NOVAT`), обсяг без ПДВ = кількість × ціна, ПДВ = обсяг × ставка.
Опис, код, одиниця й ставка за замовчуванням — з товару. Рядки, створені командами, зберігають
суми документа-підстави (ПДВ «включно» може відрізнятися від обсяг × ставка на копійку).

## БЛОК B. ПРАВИЛО ПЕРШОЇ ПОДІЇ (`trade_tax.events`)

За ключем **організація × контрагент** (договір — лише інформаційно: оплати часто без договору)
у хронологічному порядку накопичуються відвантаження S (проведені реалізації, рядки зі ставкою ПДВ,
сума «Всього») і оплати P (рухи `RECEIVABLE` оплат від покупця, ПКО, виписок; повернення коштів
покупцю — з мінусом). Податкове зобов'язання події = max(S, P) після − max(S, P) до (не менше 0):

- відвантаження без передоплати — ПН на всю суму (рядки реалізації);
- оплата після відвантаження — зобов'язання немає (`TAX_NO_LIABILITY`);
- оплата понад відвантажене — ПН на передоплату (рядок «Попередня оплата …», 20 %);
- відвантаження, покрите передоплатою, — ПН не потрібна; частково покрите — ПН на непокриту частину
  (по рядку на ставку, пропорційно сумам реалізації).

Подія з «Оформлено ПН» (сума виданих ПН з цією підставою) і «Без ПН». Повернення товарів і коштів
не зменшують зобов'язання — це розрахунки коригування (APE-302). Аванси покупців у Trade поки
заборонені регістром розрахунків, тож передоплата виникає лише після впровадження авансів.

## БЛОК C. КОМАНДИ

| Команда | Дія |
|---|---|
| Створити податкову накладну (реалізація 111, оплата від покупця 121, ПКО 371) | чернетка ПН на неоформлений залишок зобов'язання підстави; немає — `TAX_NO_LIABILITY` / `TAX_INVOICE_EXISTS` |
| Зареєструвати отриману ПН (надходження 51) | чернетка отриманої ПН з рядків надходження зі ставкою ПДВ; постачальник — платник (`TAX_SUPPLIER_NOT_VAT_PAYER`) |
| Створити ПН за першою подією (реєстр 630) | `generate`: ПН за всіма подіями періоду із залишком, одразу проведені |
| Провести | організація-платник; рядки є, обсяги > 0; видана з підставою — підставу проведено, Σ ПН підстави ≤ зобов'язання першої події (`TAX_INVOICE_EXCEEDS_BASE`); отримана — № постачальника, ІПН постачальника; знімок ІПН; рухи `RegVatLedger` за ставками |
| Скасувати проведення | надіслану / зареєстровану в ЄРПН — заборонено (`TAX_INVOICE_IN_ERPN`) |
| Надіслано / Зареєстровано / Відхилено ЄРПН | `set_erpn`; реєстрація — з реєстраційним номером (`TAX_ERPN_NUMBER`); зареєстровану не повернути (`TAX_ERPN_REGISTERED`) |
| Вивантажити XML (ЄРПН) | спрощена структура J1201016 (UTF-8, без КЕП) — для перевірки й ручного імпорту |
| Друк | «Податкова накладна»: продавець / покупець з ІПН, тип причини, рядки з кодом УКТ ЗЕД і кодом ставки (20 / 7 / 901 / 903), обсяги за ставками, стан ЄРПН і строк реєстрації |

Строк реєстрації: складена 1–15 числа — до останнього дня місяця, 16–31 — до 15 числа наступного
(`erpn_deadline`); прострочені незареєстровані позначаються в списку й реєстрі.
