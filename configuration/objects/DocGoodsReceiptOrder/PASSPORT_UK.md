# Паспорт документа «Прибутковий ордер на товари»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-65).
- Ревізія: `r5` (базова реалізація F-WH-11; розширення — `F-WH-12`, APE-278).
- Розділ меню (Taxi): `Склад` → група «Ордерний склад».
- Залежності: `RefWarehouse` (`useOrderScheme`, `useStorageBins`), `RefStorageBin`, `RefProduct`,
  `RefProductCharacteristic`, `RefProductSeries`, `RegGoodsOrderScheme`, `RegBinStock`, `RegStockBalance`.
- Аналог у 1С:УТ 11: Документ.ПриходныйОрдерНаТовары (спрощено: розпорядження обов'язкове, один
  документ-підстава на ордер, без статусів «До приймання / Приймається», без місць і упаковок).
- Функції каталогу: `F-WH-11`.

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Технічне ім'я | `DocGoodsReceiptOrder` |
| Таблиці | `doc_goods_receipt_order`, `doc_goods_receipt_order_goods` |
| Сторінки APEX | 560 — список, 561 — форма |
| Нумерація | `doc_goods_receipt_order_num_seq`, 9 цифр |
| recorder_type | `DocGoodsReceiptOrder` (v_recorder, сторінка 561) |
| Права | «Роль: склад» (Комірник, Адміністратор) |
| Друк | `RECEIPT_ORDER` — «Прибутковий ордер на товари» (`trade_order_scheme.print_html`) |

Фактичне приймання товарів комірником на ордерному складі за документом менеджера
(розпорядженням), окремо від обліку надходження.

### 2. Поля шапки

| Поле | Назва | Обов'язкове | Правила |
|---|---|---|---|
| `number`, `occurredAt` | Номер, Дата | так | стандартні |
| `organizationId` | Організація | так | з розпорядження (`trade_org.resolve_doc_org`), лише перегляд |
| `warehouseId` | Склад | так | активний, з ордерною схемою (`ORDER_SCHEME_NOT_USED`) |
| `basisId` / `basisType` | Розпорядження | так (`ORDER_BASIS_REQUIRED`) | проведений документ з товарами до надходження на цьому складі (`ORDER_BASIS_INVALID`); тип — з регістру |
| `binId` | Комірка розміщення | ні | комірка складу (`STORAGE_BIN_OTHER_WAREHOUSE`), підставляється в рядки без комірки |
| `comment`, `status`, `version`, аудит | — | — | стандартні; проведений — лише читання |

### 3. Таблична частина «Товари»

| Поле | Правила |
|---|---|
| `productId`, `characteristicId`, `seriesId` | лише товари; перевірка належності характеристики / серії (`trade_series.check_line`) |
| `quantity` | > 0, дробність одиниці |
| `binId` | комірка складу документа; обов'язкова для складу з адресним зберіганням (`ORDER_BIN_REQUIRED`) |
| «Очікується» | transient: `line_expected` — залишок до надходження ключа за розпорядженням без цього ордера |

## БЛОК B. КОМАНДИ Й ЛОГІКА (пакет `trade_order_scheme`)

| Команда | Процедура | Дія |
|---|---|---|
| Створити прибутковий ордер (у надходженні, поверненні від клієнта, оприбуткуванні, переміщенні, комплектації; робоче місце 590) | `create_order('RECEIPT', basis)`, `create_task(key)` | чернетка зі складом розпорядження й рядками за залишком до надходження; без залишку — `ORDER_NOTHING_PENDING` |
| Заповнити за розпорядженням | `fill_from_basis` | замінює рядки ключами (товар × характеристика × серія) з залишком |
| Сканер (Додати) | `scan` | штрихкод / артикул / код / назва → рядок товару, у якому ще не набрано очікуване, інакше новий рядок з ключем розпорядження |
| Провести | `post` | рядки без характеристики / серії отримують єдиний очікуваний ключ; комірка з шапки; рух `RegGoodsOrderScheme` −кількість; залишок ключа ≥ 0 (`ORDER_EXCEEDS_BASIS`); склад з комірками — `RegBinStock` +кількість |
| Скасувати проведення | `unpost` | видаляє рухи; прийняте не має бути вже відвантажене — фактичний залишок (`ORDER_PHYSICAL_STOCK`) і залишок комірки (`BIN_STOCK_INSUFFICIENT`) ≥ 0 |
| Скопіювати (F9) | `copy` | чернетка з шапкою й рядками |

`RegStockBalance` / `RegStockCost` ордер не змінює (облік веде документ менеджера). Документ
менеджера з проведеним ордером не можна скасувати чи перепровести (`ORDER_BASIS_HAS_ORDERS`).
