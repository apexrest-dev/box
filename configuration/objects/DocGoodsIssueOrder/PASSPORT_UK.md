# Паспорт документа «Видатковий ордер на товари»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-65).
- Ревізія: `r5` (базова реалізація F-WH-11; статуси відбору й розширення — `F-WH-13`, APE-280;
  завдання на відбір / маршрут — `F-WH-15`, APE-284).
- Розділ меню (Taxi): `Склад` → група «Ордерний склад».
- Залежності: як у `DocGoodsReceiptOrder`.
- Аналог у 1С:УТ 11: Документ.РасходныйОрдерНаТовары; розпорядженням на відвантаження є проведений
  видатковий документ менеджера (реалізація, повернення постачальнику, списання, переміщення,
  комплектація) на ордерному складі — окремого документа «Розпорядження» немає (спрощення).
- Функції каталогу: `F-WH-11`.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|
| Технічне ім'я | `DocGoodsIssueOrder` |
| Таблиці | `doc_goods_issue_order`, `doc_goods_issue_order_goods` (структура як у прибуткового ордера; `binId` шапки не використовується) |
| Сторінки APEX | 570 — список, 571 — форма |
| recorder_type | `DocGoodsIssueOrder` (v_recorder, сторінка 571) |
| Права | «Роль: склад» |
| Друк | `ISSUE_ORDER` — «Видатковий ордер на товари» |

Рядки: товар, характеристика, серія, кількість, комірка відбору; transient «Очікується»
(залишок до відвантаження) і «У комірці» (`bin_qty`).

## БЛОК B. КОМАНДИ Й ЛОГІКА

| Команда | Дія |
|---|---|
| Створити видатковий ордер (у реалізації, поверненні постачальнику, списанні, переміщенні, комплектації; робоче місце 590) | чернетка за залишком до відвантаження |
| Заповнити за розпорядженням | для складу з комірками — **відбір**: кількість ключа розподіляється по комірках із залишком (за адресою), решта — рядок без комірки |
| Сканер | як у прибутковому ордері; новий рядок отримує першу комірку з залишком ключа |
| Провести | рух `RegGoodsOrderScheme` −кількість (≤ очікуваного, `ORDER_EXCEEDS_BASIS`); склад з комірками — комірка обов'язкова, `RegBinStock` −кількість, залишок комірки ≥ 0 (`BIN_STOCK_INSUFFICIENT`); фактичний залишок ≥ 0 — не можна відвантажити ще не прийнятий товар (`ORDER_PHYSICAL_STOCK`) |
| Скасувати проведення | видаляє рухи (товар знову «до відвантаження») |

Стан розпорядження: «До відбору» → «Відвантажено частково» → «Відвантажено» (`v_goods_order_basis`).
Статус «Відібрано» (відбір без відвантаження) — у `F-WH-13`.
