# Паспорт регістру відомостей «Обмеження ручних знижок»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-64).
- Ревізія: `r5`.
- Розділ меню (Taxi): `Ціноутворення` → «Знижки».
- Залежності: ролі застосунку APEX (ACL: `ADMIN`, `SALES`, `PURCHASE`, `STOREKEEPER`, `CASHIER`);
  використовують рядки `DocCustomerOrder`, `DocGoodsSale` (ручна знижка), `RefDiscount`.
- Аналог у 1С:УТ 11: регістр «Обмеження скидок» (за групами користувачів); спрощено — за ролями.
- Функції каталогу: `F-PRC-06`.

## БЛОК A. СТРУКТУРА

| Параметр | Значення |
|---|---|

| Технічне ім'я | `RegDiscountLimit` |
| Таблиця | `reg_discount_limit` (незалежний, неперіодичний) |
| Сторінка APEX | 530 — таблиця з редагуванням |
| Права | «Роль: адміністратор» |

| Поле | Назва | Тип | Обов'язкове | Правила |
|---|---|---|---|---|
| `roleStaticId` | Роль | String(30) (статичний ID ролі APEX) | так | вимір, UNIQUE |

| `note` | Примітка | String(255) | ні | — |
| `updatedAt`, `updatedBy` | Змінив | — | server | — |

Початкові записи: `SALES` — 10 %, `ADMIN` — 100 %.

## БЛОК B. ЛОГІКА (`trade_discount.manual_limit` / `check_manual`, db/39)

- Обмеження користувача = найбільше з обмежень його ролей; роль без запису не обмежує (100 %);
  користувач без ролей — 0 %.
- Перевіряється тригерами рядків замовлення клієнта й реалізації, коли ручна знижка задається
  або змінюється (`MANUAL_DISCOUNT_LIMIT`), і командою «Ручна знижка на документ».
- Не перевіряється: поза сеансом APEX (скрипти, інтеграції), під час перенесення знижок у
  реалізацію на підставі замовлення та в копію документа, для автоматичних знижок.
