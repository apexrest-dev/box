# Паспорт документа «Коригування боргу» (взаємозалік, списання, перенесення заборгованості)

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08 (Linear APE-55), реалізовано без формального
  погодження (як r2–r4); потребує явного погодження користувача.
- Ревізія: `r4`.
- Розділ основного меню: `Документи`; панель функцій `Фінанси` (група «Взаєморозрахунки», важливе).
- Залежності: `RefOrganization`, `RefCounterparty`, `RefContract`, `RegCounterpartySettlement`.
- Пакет: `trade_debt_adj` (db/30). Звіт-друкована форма «Акт звірки взаєморозрахунків» — той самий пакет.
- Аналог у 1С:УТ 11: Документ.КорректировкаРеализации / ВзаимозачетЗадолженности / СписаниеЗадолженности
  (у Trade об'єднано в один документ з видами операцій).
- Функція каталогу: `F-FIN-05`.

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Українська назва | Коригування боргу |
| Технічне ім'я | `DocDebtAdjustment` |
| Технічний ключ | `Document.DebtAdjustment` |
| Таблиця | `doc_debt_adjustment` (список `v_debt_adjustment_list`) |
| Нумерація | `doc_debt_adjustment_num_seq`, 9 символів, без перевикористання; ручний номер 1–9 символів |
| API | `/api/v1/documents/debt-adjustments` |
| Сторінки APEX | 410 (список), 411 (документ), 420 (акт звірки) |

Коригує заборгованість у регістрі `RegCounterpartySettlement` без руху грошей і товарів.

### 2. Поля шапки

| Поле | Назва | Тип | Обов'язкове | Правило |
|---|---|---|---|---|
| `docNumber`, `occurredAt` | Номер, дата | — | так | як у всіх документах; залишки для контролю — на дату документа |
| `organizationId` | Організація | `RefOrganization` | так | порожнє → організація за замовчуванням; активна |
| `operationKind` | Вид операції | enum | так | див. п. 3; за замовчуванням `OFFSET` (`DEBT_OPERATION_KIND`) |
| `counterpartyId` | Контрагент | `RefCounterparty` | так | активний (`DEBT_COUNTERPARTY_REQUIRED`) |
| `contractId` | Договір | `RefContract` | ні | залік — договір з покупцем; списання / перенесення — договір-джерело за напрямом; один договір виду — підставляється |
| `targetCounterpartyId` | Новий контрагент | `RefCounterparty` | для перенесення | порожнє → той самий контрагент; для заліку = контрагент; для списання очищається |
| `targetContractId` | Другий договір | `RefContract` | ні | залік — договір з постачальником; перенесення — договір-одержувач |
| `currencyCode` | Валюта | String(3) | так | лише `UAH` (як усі взаєморозрахунки) |
| `amount` | Сума | BigDecimal(19,2) | так | > 0 (`DEBT_AMOUNT`) |
| `reason` | Підстава | String(500) | ні | порожнє → назва виду операції; друкується в акті |
| `docComment`, `status`, `version`, аудит | — | — | — | як у всіх документах |

### 3. Види операцій і рухи `RegCounterpartySettlement`

| Код | Назва | Рядок 1 | Рядок 2 | Контроль |
|---|---|---|---|---|
| `OFFSET` | Взаємозалік заборгованостей | `RECEIVABLE` контрагента − сума | `PAYABLE` контрагента − сума | сума ≤ min(дебіторка, кредиторка) на дату (`DEBT_OFFSET_EXCEEDS`) |
| `WRITE_OFF_RECEIVABLE` | Списання дебіторської заборгованості | `RECEIVABLE` − сума | — | сума ≤ дебіторки (`DEBT_AMOUNT_EXCEEDS`) |
| `WRITE_OFF_PAYABLE` | Списання кредиторської заборгованості | `PAYABLE` − сума | — | сума ≤ кредиторки (`DEBT_AMOUNT_EXCEEDS`) |
| `TRANSFER_RECEIVABLE` | Перенесення дебіторської заборгованості | `RECEIVABLE` джерела − сума | `RECEIVABLE` одержувача + сума | сума ≤ дебіторки джерела; одержувач ≠ джерело (`DEBT_TRANSFER_SAME`) |
| `TRANSFER_PAYABLE` | Перенесення кредиторської заборгованості | `PAYABLE` джерела − сума | `PAYABLE` одержувача + сума | сума ≤ кредиторки джерела; одержувач ≠ джерело |

Усі рухи — з організацією документа, валюта `UAH`, період = дата документа.

### 4. Статуси й команди

`DRAFT → POSTED` (Провести), `POSTED → DRAFT` (Скасувати проведення); проведений документ лише для читання
(`DOCUMENT_READ_ONLY`) і не видаляється (`DOCUMENT_POSTED`); чернетку можна видалити. «Скопіювати (F9)» — нова
чернетка з тими самими реквізитами. «Друк» — акт взаємозаліку / коригування (сторінка 900).

## БЛОК B. UI

- Список (410): Номер, Дата, Організація, Вид операції, Контрагент, Новий контрагент, Сума, Підстава, Статус, Коментар.
- Документ (411): `Організація | Вид операції`, `Контрагент | Договір`, `Новий контрагент | Другий договір`,
  `Валюта | Сума | Підстава`, коментар. «Новий контрагент» видно лише для перенесення, «Другий договір» —
  для заліку й перенесення. Списки договорів — за вибраним контрагентом (другий — за новим контрагентом).
- Сторінки 410/411 і команди — схема «Роль: каса» (Адміністратор, Касир).
- Акт звірки (420): параметри Організація, Контрагент, З, По (за замовчуванням — з початку кварталу по сьогодні);
  «Сформувати», «Друк». Доступний усім ролям (меню «Фінанси», «Продажі», «Закупівлі» → «Звіти»).

## БЛОК C. БІЗНЕС-ЛОГІКА

- Перевірка шапки (`trade_debt_adj.check_header`, тригер): вид операції, контрагенти, договори
  (`trade_nsi.check_contract`: власник, вид, стан, строк дії), автопідстановка договорів, очищення зайвих полів.
- Проведення (`trade_debt_adj.post`): блокування документа й контрагентів, атомарна заміна рухів реєстратора,
  контроль суми за залишками **на дату документа** (без рухів самого документа), після запису —
  `trade_org.check_settlement` (пізніші документи не отримують від'ємної заборгованості).
- Скасування проведення: видалення рухів; для перенесення — перевірка, що одержувач ще не погасив / не списав
  перенесений борг (`SETTLEMENT_NEGATIVE_BY_ORGANIZATION`).
- Аудит POST / UNPOST / COPY / PRINT; формування акта звірки фіксується як PRINT (`ReconciliationAct`).

## БЛОК D. ДРУК

- `DEBT_ADJ` «Акт взаємозаліку заборгованостей» (для заліку) / «Акт коригування заборгованості» (списання,
  перенесення): організація й контрагент з реквізитами, вид операції, договори, сума цифрами й прописом,
  підстава, підписи сторін (для перенесення на іншого контрагента — і нового боржника / кредитора).
- Акт звірки взаємних розрахунків (`trade_debt_adj.reconciliation_html`): дві половини «За даними організації» /
  «За даними контрагента» (друга порожня — заповнює контрагент); сальдо на початок, рядки документів-реєстраторів
  (дебет — збільшення боргу контрагента / погашення нашого боргу, кредит — навпаки), обороти, сальдо на кінець,
  висновок «заборгованість на користь …» з сумою прописом, підписи.

## Рішення й відхилення

| Рішення | Пояснення |
|---|---|
| Один документ із видами операцій | замість трьох документів 1С (взаємозалік, списання, коригування) — однакова структура й рухи |
| Перенесення між договорами | регістр не має виміру «Договір» — перенесення між договорами одного контрагента пише пару рухів −/+ (історія в акті звірки), залишок за контрагентом не змінюється; договір як вимір — пізніша ревізія |
| Контроль на дату документа | залік / списання заднім числом не може погасити борг, що виник пізніше |
| Без рахунків бухобліку | списання безнадійного боргу не формує витрат / доходів (плану рахунків і резерву сумнівних боргів немає) |
| Лише UAH | як усі взаєморозрахунки r1–r4 |
| Аванси | переплата (від'ємна заборгованість) і далі заборонена — коригування не може її створити |
