# Паспорт регістру залишків «Взаєморозрахунки»

## 0. Стан паспорта

- Статус: `AGREED`.
- Погодження: користувач явно погодив паспорт 2026-11-03.
- Вид: накопичувальний регістр залишків.
- Технічне ім'я: `RegCounterpartySettlement`.
- Розділ основного меню: `Звіти`.
- Реєстратори: `DocGoodsReceipt`, `DocSupplierPayment` (r1); пізніші ревізії — реалізації, оплати, повернення, ПКО/ВКО, виписки, `DocDebtAdjustment` (r4, коригування боргу / взаємозалік; акт звірки — сторінка 420).

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

Клас `CounterpartySettlementMovement`, таблиця
`reg_counterparty_settlement_movement`, API `/api/v1/registers/settlements`.
Регістр зберігає суму непогашеної дебіторської або кредиторської заборгованості.

### 2. Структура руху

| Поле | Роль | Тип | Точність | Джерело | Посилання/БД |
|---|---|---|---|---|---|
| `id` | системне | UUID | — | server | PK |
| `period` | системне | Instant UTC | seconds | документ | index |
| `recorderId/type` | системне | UUID/String | — | документ | index |
| `lineNumber` | системне | int | — | mapping | unique з recorder |
| `counterpartyId` | вимір | UUID | — | документ | `RefCounterparty`, FK |
| `direction` | вимір | enum | — | mapping | `PAYABLE/RECEIVABLE` |
| `currencyCode` | вимір | String | 3 | документ | ISO 4217 |
| `amount` | ресурс | BigDecimal | 19,2 | документ | signed |

Ключ підсумку: `counterpartyId + direction + currencyCode`.

### 3. Правила залишку

Позитивний залишок означає непогашену заборгованість відповідного напрямку.
`DocGoodsReceipt` додає `PAYABLE`; `DocSupplierPayment` віднімає `PAYABLE`.
Від'ємний залишок за ключем заборонений. Поточні підсумки та місячні знімки
працюють за спільним правилом регістрів; зміна минулого інвалідує пізніші знімки.

## БЛОК B. UI

### 4. Форма списку

Read-only режими `Рухи`, `Обороти`, `Залишки`. Колонки: період, реєстратор,
контрагент, напрямок, валюта, сума. Фільтри: період, контрагент, напрямок,
валюта. Перехід до документа; пряме редагування заборонене.

### 5. Події введення

Поля рухів — `disabled`; фільтри лише виконують серверні queries.

## БЛОК C. БІЗНЕС-ЛОГІКА

### 6. Розрахунки

`balance = SUM(amount)` за ключем, scale 2, `HALF_UP`. Приклад: накладна
1 250,00 і оплата 500,00 дають `PAYABLE = 750,00`. Оплата 1 250,01 при залишку
1 250,00 відхиляється.

### 7. Формування, зберігання й API

Набір рухів реєстратора атомарно замінюється, unpost видаляє його. Таблиці
поточних підсумків/знімків похідні. Queries: movements, turnovers, balances,
rebuild. Права користувача — лише `read`; запис тільки через проведення.

### 8. Тести й готовність

Знаки, валюта, напрямки, заборона переплати, repeat/unpost, місячний rebuild,
SQLite/PostgreSQL, конкурентність, API і read-only UI.
