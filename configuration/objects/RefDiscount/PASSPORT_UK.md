# Паспорт довідника «Знижки та акції»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-64).
- Ревізія: `r5`.
- Розділ меню (Taxi): `Ціноутворення` → «Знижки»; `Продажі` → «НСІ»; звіт «Надані знижки» —
  `Ціноутворення` / `Продажі` / `Головне` → «Звіти».
- Залежності: `RefCounterparty`, `RefContract`, `RefProductGroup`, `RefProduct`;
  використовують `DocCustomerOrder` r5, `DocGoodsSale` r5; обмеження — `RegDiscountLimit`.
- Аналог у 1С:УТ 11: Справочник.СкидкиНаценки + умови надання (спрощено: лише знижки у
  відсотках, без націнок, накопичувальних, подарункових і бонусних знижок, без сумісності /
  пріоритетів груп — з кількох придатних умов діє одна з найбільшим відсотком). Каталог
  об'єктів передбачав регістр `RegDiscount`; умови оформлено довідником, бо вони мають
  власні реквізити, помітку на видалення й журнал змін.
- Функції каталогу: `F-PRC-06`.

## БЛОК B. ЛОГІКА (пакет `trade_discount`, db/39)

- **Рядки документів.** Замовлення клієнта: `discountPercent` (r3) тепер підсумкова знижка =
  `manualDiscountPercent` «Ручна знижка» + `autoDiscountPercent` «Автоматична знижка» (≤ 100 %),
  `discountId` — застосована умова. Реалізація: `basePrice` «Ціна до знижки» + ті самі поля;
  `price` — ціна зі знижкою (обчислюється, нею користуються суми, RegSales, борг, повернення,
  контроль націнки). Вставка / зміна лише `discountPercent` (замовлення) або лише `price`
  (реалізація) — API r2–r4 — сприймається як ручна знижка / нова ціна до знижки.
- **Умова рядка** (`best_rule`): активна, застосування `ALL` або тип документа, дата документа в
  періоді, покупець / договір / товар / група (з підгрупами) документа й рядка, кількість рядка ≥
  мінімальної, сума документа до знижок ≥ мінімальної. З кількох — одна з найбільшим відсотком
  (за рівності — менший код). Автоматичні знижки не сумуються між собою; ручна додається.
- **«Розрахувати знижки»** (`calc`, сторінки 111 / 261, лише чернетка, журнал `CALC_DISCOUNTS`).
  Під час проведення замовлення й реалізації автоматичні знижки перераховуються (`prepare_post`,
  виклик з `trade_r3.post_customer_order` / `trade_ops.post_goods_sale`); реалізація на підставі
  замовлення не перераховується — ціна до знижки, ручна й автоматична знижка та умова
  переносяться з рядка замовлення (`sale_line_from_order`, раніше знижка «зашивалась» у ціну).
- **«Ручна знижка на документ»** (`set_manual`) — однаковий ручний відсоток у всіх рядках
  (журнал `SET_MANUAL_DISCOUNT`), з контролем обмеження ролі (`RegDiscountLimit`).
- Копіювання документа переносить ціну до знижки й знижки (`copy_lines`, процес копіювання
  сторінок 111 / 261).
- **Звіт 540 «Надані знижки»** (`v_discount_given`, `given_html`): за період і організацію —
  підсумки за умовами (рядків, сума без знижки, сума знижки, у т. ч. автоматична / ручна —
  пропорційно відсоткам, частка) і рядки проведених реалізацій зі знижкою з посиланням на документ.

## Відхилення / межі r5

- Рахунок на оплату на підставі замовлення, як і раніше, містить ціну зі знижкою (без колонок знижок).
- Реалізації на підставі замовлень, створені до r5, мають знижку в ціні (у звіті не показуються).
- Друковані форми реалізації показують ціну зі знижкою без окремої колонки знижки.
- Умови за сегментами / видами цін / складами, накопичувальні й бонусні знижки — поза межами r5.
