# Паспорт регістру відомостей «Курси валют»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-66).
- Ревізія: `r5`.
- Розділ меню (Taxi): `Фінанси` → «Казначейство»; `НСІ та адміністрування` → «Підприємство».
- Залежності: `RefCurrency`; використовують звіти коштів (`RegCashBalance`, сторінка 360).
- Аналог у 1С:УТ 11: РегистрСведений.КурсыВалют (періодичний, по дню; завантаження з сайту НБУ).
  У каталозі функцій — `RegExchangeRate`; технічне ім'я в Trade — `RegCurrencyRate`.
- Функції каталогу: `F-FIN-06`.

## БЛОК B. ЛОГІКА (`trade_currency`, db/41)

- `rate(code, date)` — зріз останніх: запис з найбільшою датою ≤ дати; UAH = 1; немає курсу — null.
  `rate_date`, `to_uah(amount, code, date)` (округлення до копійки), `convert_amount(amount, from, to, date)`
  (через гривню), `set_rate` (merge за валютою й датою).
- НБУ: `parse_nbu(json)` — розбір відповіді `https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json&date=YYYYMMDD`
  (`cc`, `rate`, `exchangedate`); записуються лише активні валюти довідника з ознакою «Завантажувати курс НБУ».
  `load_nbu(date)` — HTTPS-запит через `apex_web_service` (мережевий ACL APEX), помилка → `NBU_HTTP`, журнал
  `NBU_LOAD`; `load_nbu_period(from, to)` — до 93 днів (`NBU_PERIOD`).
- Щоденне завдання `TRADE_NBU_RATES` (DBMS_SCHEDULER, 09:30) — `trade_currency.load_nbu_today`.
- Встановлення db/41 завантажує курси НБУ за 14 днів; без мережі — фіксовані демо-курси.

## БЛОК C. UI

Сторінка 610: панель «Завантаження курсів НБУ» (період з / по, кнопка «Завантажити курси НБУ»), таблиця
курсів (валюта, дата, курс, кратність, джерело, примітка, змінив) з додаванням / зміною / видаленням.
