# Паспорт документа «Чек ККМ»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08, потребує явного погодження користувачем
  для переведення в `AGREED` (реалізовано за загальним дорученням користувача, APE-68).
- Ревізія: `r5`.
- Розділ меню (Taxi): `Продажі` → «Роздрібні продажі» (Робоче місце касира, Чеки ККМ).
- Залежності: `RefCashRegister`, `RefProduct` (товари й послуги), `RegProductPrice` (роздрібна ціна),
  `RefVatRate`, `RegStockBalance`, `RegStockReserve`, `RegStockCost`, `RegSales`, `RegCashBalance`,
  `RefProductSeries` (FEFO).
- Аналог у 1С:УТ 11: Документ.ЧекККМ + форма «РМК» (спрощено: кожен чек проводиться одразу, без
  «Звіту про роздрібні продажі» за зміну; касові зміни X/Z — APE-179, чек повернення — APE-187,
  еквайринг — APE-183, відкладені чеки — APE-192, магазини й роздрібні склади — APE-176).
- Функції каталогу: `F-RET-01`.

### Шапка

| Поле | Назва | Правила |
|---|---|---|
| `number`, `occurredAt` | Номер, Дата | стандартні |
| `cashRegisterId` | Каса ККМ | активна; визначає поля нижче (заповнюються тригером при кожному записі) |
| `organizationId`, `warehouseId`, `cashDeskId`, `bankAccountId`, `customerId`, `priceTypeId` | — | з каси ККМ |
| `receiptKind` | Вид | `SALE`; `RETURN` і `baseReceiptId` — резерв для чека повернення (APE-187, зараз `RETAIL_RETURN_NOT_SUPPORTED`) |
| `shiftId` | Касова зміна | резерв для APE-179 |
| `totalAmount`, `vatAmount` | Сума, у т. ч. ПДВ | Σ рядків (лише тригером) |
| `paidCash`, `paidCard` | Отримано готівкою, Оплата карткою | ≥ 0; картка ≤ суми; готівка + картка ≥ суми; обидва порожні — готівкою без решти |
| `changeAmount` | Решта | готівка + картка − сума (лише проведенням) |
| `fiscalStatus` | ПРРО | `PENDING` / `FISCALIZED` / `NOT_FISCAL` |
| `fiscalNumber`, `fiscalAt`, `fiscalUrl`, `fiscalPayload` | Фіскальний номер, час, посилання на перевірку, JSON-запит | лише `trade_prro` |
| `cashierName`, `comment`, `status`, `version`, аудит | — | проведений — лише читання |

### Рядки «Товари»

| Поле | Правила |
|---|---|
| `productId` | товар або послуга, активний |
| `characteristicId`, `seriesId` | як у реалізації; порожня серія — FEFO під час проведення (без прострочених) |
| `quantity` | > 0, дробність одиниці |
| `price` | порожньо — роздрібна ціна виду цін каси на дату чека; немає ціни — `RETAIL_PRICE_NOT_SET` |
| `amount` | кількість × ціна (з ПДВ) |
| `vatRateCode`, `vatAmount` | ставка товару (організація не платник — `NOVAT`); ПДВ = сума × r / (100 + r) |
| `costAmount` | собівартість — лише проведенням |

## БЛОК B. КОМАНДИ Й ЛОГІКА (`trade_retail`, `trade_prro`)

| Команда | Процедура | Дія |
|---|---|---|
| Сканер (РМК, форма) | `scan(register, receipt, text)` / `doc_scan` | штрихкод / артикул / код / назва; «3*код» — кількість; той самий товар без серії — збільшення рядка; без чека — створює чернетку; товар з характеристиками — лише у формі (`RETAIL_CHARACTERISTIC_REQUIRED`) |
| +1 / −1 / × | `change_qty`, `set_qty`, `delete_line` | кількість ≤ 0 — рядок видаляється |
| Оплата готівкою / карткою / змішана | `pay(receipt, cash, card)` | записує оплату й проводить (`post`) |
| Скасувати чек (РМК) | `cancel_receipt` | видаляє чернетку |
| Провести | `post` | контроль оплати (`RETAIL_UNDERPAID`, `RETAIL_CARD_EXCEEDS_TOTAL`), рухи, фіскалізація |
| Скасувати проведення | `unpost` | лише нефіскалізований чек (`RETAIL_FISCALIZED`) |
| Скопіювати | `copy` | чернетка з товарами за поточними цінами |
| Підібрати серії (FEFO) | `trade_series.fill_fefo` | як у реалізації |

### Рухи

| Регістр | Рух |
|---|---|
| `RegStockBalance` | −кількість товарів (послуги не рухають склад); контроль вільного залишку |
| `RegStockCost` | −середня ковзна (`trade_r3.out_cost`); `trade_r3.rebuild_stock_cost` враховує чеки |
| `RegSales` | рядки: роздрібний покупець, склад, кількість, сума з ПДВ |
| `RegCashBalance` | каса: + (сума − картка), `RETAIL_SALE`; рахунок каси ККМ: + картка, `RETAIL_CARD` (немає рахунку — попередження `RETAIL_CARD_NO_ACCOUNT`) |

### ПРРО (`trade_prro`)

Заглушка без звернення до ДПС / Checkbox: фіскальна каса — лічильник `fiscalSeq` + 1, фіскальний номер
чека «ФН ПРРО.000001», посилання `https://cabinet.tax.gov.ua/cashregs/check?...`, JSON-запит у форматі,
близькому до Checkbox API (суми в копійках, кількість × 1000, оплати CASH / CASHLESS, решта); нефіскальна
каса — `NOT_FISCAL`. Інші провайдери — `PRRO_PROVIDER_NOT_SUPPORTED`. Фіскалізований чек не скасовується й
не проводиться повторно — лише чек повернення (APE-187). Z-звіт і зміни — APE-179.

### ПДВ

Ціни роздрібу включають ПДВ; ставка — з номенклатури; у чеку — ПДВ за ставками (А — 20 / 7 / 0 %, Б — без ПДВ).
Податкове зобов'язання за роздрібом (зведена ПН) у r5 не формується — правило першої події (APE-67) працює
від взаєморозрахунків, які чек не рухає.
