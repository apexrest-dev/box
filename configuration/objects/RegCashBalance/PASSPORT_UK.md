# Паспорт регістру залишків «Грошові кошти»

## 0. Стан паспорта

- Статус: `PROPOSED` — підготовлено 2026-11-08 (Linear APE-52), реалізовано без формального
  погодження (як r2–r4); потребує явного погодження користувача.
- Ревізія: `r4`.
- Вид: накопичувальний регістр залишків.
- Технічне ім'я: `RegCashBalance`.
- Розділ основного меню: `Звіти`; панель функцій `Фінанси` (група «Звіти»).
- Залежності: `RefOrganization`, `RefCashDesk`, `RefBankAccount` (F-FIN-01).
- Реєстратори: «Введення залишку коштів» (`CashOpeningBalance`, r4); надалі — `DocCashReceipt` /
  `DocCashPayment` (ПКО/ВКО, APE-53), `DocBankStatement` (APE-54), оплати з джерелом коштів
  `DocCustomerPayment` / `DocSupplierPayment` (APE-56/57).
- Аналог у 1С:УТ 11: РегистрНакопления.ДенежныеСредстваНаличные / ДенежныеСредстваБезналичные
  (об'єднано в один регістр з виміром «вид місця зберігання»).
- Функція каталогу: `F-FIN-02`.

## БЛОК A. СТРУКТУРА

### 1. Ідентичність і призначення

| Параметр | Значення |
|---|---|
| Українська назва | Грошові кошти |
| Технічний ключ | `AccumulationRegister.CashBalance` |
| Таблиця рухів | `reg_cash_balance_mv` |
| Підсумки / знімки | `reg_cash_balance_tot` / `reg_cash_balance_snap` |
| Представлення | `v_cash_place`, `v_cash_movement`, `v_cash_balance` |
| Пакет | `trade_cash` |
| API | `/api/v1/registers/cash` |
| Сторінка APEX | 360 «Залишки й обороти коштів» |

Регістр зберігає залишок грошей у кожній касі й на кожному банківському рахунку організації у
валюті місця зберігання.

### 2. Структура руху

| Поле | Роль | Тип | Точність | Джерело | Посилання/БД |
|---|---|---|---|---|---|
| `id` | системне | UUID | — | server | PK |
| `period` | системне | дата-час | seconds | документ | index |
| `recorderType/Id` | системне | String/UUID | — | документ | UNIQUE з `lineNumber` |
| `lineNumber` | системне | int | — | mapping | — |
| `organizationId` | вимір | `RefOrganization` | — | з каси/рахунку | FK |
| `placeKind` | вимір (вид місця) | enum | — | mapping | `CASH_DESK` / `BANK_ACCOUNT` |
| `cashDeskId` / `bankAccountId` | вимір «каса / банківський рахунок» | `RefCashDesk` / `RefBankAccount` | — | документ | FK, рівно одне заповнене |
| `currencyCode` | вимір | String | 3 | з каси/рахунку | ISO 4217 |
| `amount` | ресурс | BigDecimal | 19,2 | документ | signed, ≠ 0; `+` надходження, `−` витрата |
| `operationKind` | реквізит | String | 30 | документ | `OPENING`, `RECEIPT`, `PAYMENT`, … |
| `content` | реквізит | String | 255 | документ | зміст операції |

Ключ підсумку: `organizationId + placeId (каса або рахунок) + currencyCode`.

### 3. Правила залишку

- Організація й валюта руху визначаються місцем зберігання; невідповідність, передана явно, —
  помилка `CASH_PLACE_ORGANIZATION` / `CASH_PLACE_CURRENCY`.
- Від'ємний залишок каси (`CASH_BALANCE_NEGATIVE`) і банківського рахунку (`BANK_BALANCE_NEGATIVE`)
  заборонений **на кожен момент часу** від найранішої дати, змінену проведенням чи скасуванням:
  витрата заднім числом не може «позичити» гроші з пізнішого надходження, скасування ПКО неможливе,
  якщо гроші вже витрачено.
- Організацію й валюту каси / рахунку з рухами змінювати не можна (`CASH_PLACE_HAS_MOVEMENTS`).
- Поточні підсумки ведуться тригером рухів; знімки на кінець місяця — `trade_regs.close_month`;
  зміна минулого інвалідує пізніші знімки; `trade_regs.rebuild_totals` перебудовує з рухів.

## БЛОК B. UI

Сторінка 360 «Залишки й обороти коштів», відбір «Організація», режими:

- **Залишки** — організація, вид, код, каса / рахунок, валюта, залишок (з підсумків);
- **Обороти** — за період: поч. залишок, надходження, витрата, кін. залишок;
- **Рухи** — період, реєстратор (посилання), організація, місце, валюта, надходження, витрата, зміст;
- **Введення залишків** — каса / рахунок, дата, сума, «Записати залишок»; список введених залишків.

Сторінка й кнопка запису — схема «Роль: каса» (Адміністратор, Касир). Пряме редагування рухів заборонене.

## БЛОК C. БІЗНЕС-ЛОГІКА

### 4. API проведення (`trade_cash`)

| Процедура | Призначення |
|---|---|
| `delete_movements(type, id)` | видалити набір реєстратора (повторне проведення / скасування), запам'ятати місця |
| `add_movement(type, id, period, line, placeKind, placeId, amount, operationKind, content)` | рух у режимі проведення (`trade_core.g_internal`); нуль не пишеться; сума округлюється до 2 знаків |
| `check_balances` | контроль від'ємного залишку на всіх змінених місцях; викликати в кінці проведення та скасування |
| `set_opening_balance(placeKind, placeId, date, amount)` | введення / заміна початкового залишку (реєстратор `CashOpeningBalance`, recorder_id = місце) |
| `balance(placeId)`, `balance_at(placeId, at)` | поточний залишок і залишок на момент (знімок + рухи) |

Приклад: залишок каси 1 000,00; ВКО 300,00 → 700,00; ВКО 800,00 відхиляється
(«матиме від'ємний залишок −100,00 UAH»).

### 5. Тести й готовність

`db/tests/t08_cash_register.sql` (41 перевірка): заборона прямого запису, введення залишків, виміри

скасування), знімки, залишок на дату, інвалідація, перебудова, звіт, меню й права;
`t04_totals_consistency.sql` — узгодженість підсумків.

### 6. Відхилення

| Рішення | Пояснення |
|---|---|
| Один регістр для каси й банку | вимір «вид місця» замість двох регістрів 1С; спільний звіт |
| Сума лише у валюті місця | регламентований еквівалент у гривні — з `RefCurrency` і курсами (r5) |
| Статті руху коштів | немає довідника (поза r4); реквізити `operationKind` / `content` |
| Введення залишків | службовий реєстратор `CashOpeningBalance` (без окремого документа) |
| Контроль банківського рахунку | як і каси (овердрафт не підтримується) |
