# Каркас основної системи Trade

## Межі

Основна система є модульним монолітом із двома процесами: Spring Boot сервером і JavaFX-клієнтом. Сервер володіє даними, транзакціями, правами та бізнес-правилами. Клієнт не має JDBC-залежностей і не працює з БД напряму.

```text
client -> HTTPS /api/v1 -> server -> application ports -> SQLite або PostgreSQL
                  |             |
          shared-contracts   domain-core
client -> ui-library
```

## Доменне ядро

`domain-core` задає невеликі типізовані основи `CatalogItem`, `Document`, `AccumulationRegister`, `InformationRegister` і `Constant`. Це не універсальна метамодель і не набір динамічних JSON-полів. Конкретні об'єкти отримають власні класи й таблиці після погодження паспорта.

Рухи регістрів є джерелом істини. Залишки, обороти та знімки будуть реалізовані окремими query/application-компонентами, а не змінюваними полями JavaFX.

## Persistence

Профіль `sqlite` призначений для локального однокористувацького сервера, `postgresql` — для мережевого режиму. Спільні міграції лежать у `server/src/main/resources/db/migration/common`. Діалектні міграції можна додавати лише до окремих каталогів адаптерів, з однаковою доменною семантикою.

Початкова міграція створює тільки системні таблиці аудиту та ідемпотентності. Таблиці предметної області не створюються до погодження паспорта відповідного об'єкта.

## API й помилки

API починається з `/api/v1`. Correlation ID приймається або генерується сервером і повертається в заголовку. Помилка має стабільний DTO: код, повідомлення, перелік помилок валідації та correlation ID.

## UI

Форми створюються Java-кодом, без FXML і без автогенерації runtime-форм із метаданих. `ui-library` містить базові контроли, але не бізнес-правила. Пошук посилань асинхронний; довгі та мережеві операції не виконуються на JavaFX Application Thread.

## Порядок додавання об'єкта

1. Погодити паспорт об'єкта.
2. Додати доменні типи й тести.
3. Додати application-команди, запити та порти.
4. Додати міграції й адаптери SQLite/PostgreSQL.
5. Додати DTO та `/api/v1` endpoints.
6. Реалізувати форми JavaFX на стандартних контролах.
7. Перевірити вертикальний сценарій і обидві СУБД.
